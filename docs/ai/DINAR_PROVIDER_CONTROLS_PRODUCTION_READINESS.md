## 2. مراجعة البنود المطلوبة

| البند | الحالة | الدليل والحدود |
|---|---|---|
| تعدد العمليات والنسخ | **حد موثق، دون بنية موزعة** | الحالة في ذاكرة العملية. كل نسخة تحمي نفسها وتتعلم التعطل وحدها (حتى N طلبات فاشلة لكل نسخة). المفتاح متسق لأنه يُقرأ من البيئة في كل طلب. لم يُبنَ مخزن مشترك لعدم وجود دليل حاجة: DINAR يعمل اليوم نسخة واحدة. إن تعددت النسخ فالتكلفة الإضافية في أسوأ حال N×النسخ طلبات فاشلة لكل تبريد، وهي غير مفوترة غالبًا (أخطاء اتصال) |
| عزل المزود عن النموذج | ✅ | PC-06. مفتاح `OPENAI` يعطل المزود كله، و`OPENAI:model` نموذجًا واحدًا، و`*` الكل |

### توقعات التشغيل مع عدة نسخ (replicas)

لم تُضف Redis ولا اعتمادية موزعة: DINAR يعمل نسخة واحدة، ولا متطلب نشر يبرر ذلك.

| السلوك | مع N نسخة |
|---|---|
| مفتاح التعطيل | متسق فورًا بعد إعادة نشر البيئة على كل النسخ (يُقرأ في كل طلب) |
| القاطع | مستقل لكل نسخة. أسوأ حال قبل أن تفتح كلها: N × `DINAR_AI_BREAKER_FAILURES` طلبًا فاشلًا لكل تبريد. أخطاء الاتصال غالبًا غير مفوترة |
| التجربة نصف المفتوحة | تجربة واحدة لكل نسخة، أي حتى N تجربة متزامنة عبر النسخ |
| سقف HEAVY والحصص والإنفاق | **مشتركة**، لأنها في PostgreSQL: لا تتضاعف مع N |
| التنبيه | حدث لكل نسخة: يُجمَّع في أداة السجل حسب `provider` و`model` |
| بعد إعادة التشغيل | القاطع يبدأ مغلقًا. للتعطيل الدائم يُستخدم المفتاح لا القاطع |

**متى تلزم حالة مشتركة:** إن صار N كبيرًا، أو صار خطأ المزود مفوترًا، أو احتجنا تعطيلًا فوريًا دون إعادة نشر. حينها يُخزَّن القاطع والمفتاح في PostgreSQL القائمة (جدول صغير)، قبل التفكير في Redis.

## 3. الإعداد

| المتغير | المعنى | الافتراضي |
|---|---|---|
| `DINAR_AI_DISABLED_PROVIDERS` | `*` أو `OPENAI` أو `OPENAI:model`، مفصولة بفواصل، دون حساسية لحالة الأحرف | فارغ |
| `DINAR_AI_BREAKER_FAILURES` | عدد التعطلات المتتالية التي تفتح القاطع (1–100). `0` يوقفه | 5، و0 في اختبارات النموذج المحجوب |
| `DINAR_AI_BREAKER_COOLDOWN_MS` | مدة التبريد، وهي أيضًا مهلة التجربة (1000–3600000) | 60000 |

## 4. ما لم يُفعل عمدًا

- لا مخزن موزع للحالة: لا دليل حاجة، ونسخة واحدة اليوم.
- لا لوحة إعداد حية.
- لا اتصال بمزود حقيقي: كل الأدلة هنا بدائل اختبار.
