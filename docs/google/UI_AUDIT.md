## 2. ما يعمل جيدًا (لا نكسره)

- `lang="ar" dir="rtl"` على الجذر، وخط عربي واحد من Google Fonts (الاستثناء الوحيد المسموح في CSP).
- رابط «تخطّي إلى المحتوى» (`href="#main"`) و`aria-label` على أزرار الشريط كلها تقريبًا.
- `:focus-visible` عام و`prefers-reduced-motion` موجودان في `index.css`.
- **بطاقة كونيكت:** لا تعرض «تم» إلا بعد `status === "EXECUTED"` من الخادم، وتفصل بيانات المتجر عن كلام جاسم. هذا السلوك يجب أن يبقى حرفيًا.
- حماية `safeNext` للتوجيه بعد الدخول، وحقل رمز SMS بـ`autoComplete="one-time-code"` و`inputMode="numeric"`.
- أزرار مخفية/معطلة حسب `active`، ورسائل خطأ عربية لحالات الرفض.

## 3. الجوال و RTL وإمكانية الوصول — قائمة فحص للتحقق بالتشغيل

| المجال | ما ثبت من الكود | ما يلزم قياسه |
|---|---|---|
| الجوال 320px | `viewport-fit=cover` + `safe-area-inset` مستخدمان في التهيئة | تمرير أفقي في الجداول/البطاقات، تغطية لوحة المفاتيح لمربع الكتابة |
| RTL | الجذر RTL؛ أغلب الكود منطقي | الأرقام/الهواتف/الأسعار (`dir="ltr"` موضعي)، اتجاه الأسهم (`ArrowLeft` في «التالي» صحيح لـRTL) |
| التباين | `--muted-foreground` 216 15% 42% على خلفية 97% | قياس WCAG AA فعلي للنصوص الصغيرة، والذهبي كنص على الأبيض (يوجد `--accent-ink` للتعامل معه) |
| لوحة المفاتيح | تركيز ظاهر عام؛ حوار التهيئة عبر Radix | ترتيب Tab في البطاقات، إدارة التركيز بعد «تأكيد/إلغاء» في بطاقة كونيكت (حاليًا يختفي الزران دون نقل التركيز) |
| قارئ الشاشة | `role="status"` في كونيكت | `aria-live` لأخطاء الدخول، وإعلان تقدم خطوات SMS |

## 4. الصفحات الناقصة أو المربكة

- **«نسيت كلمة المرور»:** لا أثر لها في `Auth.tsx`. **ليست من نطاقي**: طلب للمالك إن كان المسار موجودًا في الخادم (لن أضيف زرًا لميزة غير موجودة).
- **صفحة 404 / رابط غير صالح:** غير قابلة للوصول (البند 11).
- **صفحة حالة الجلسة المنتهية:** `Protected` يعرض نموذج الدخول مباشرة دون سبب؛ يلزم سطر «انتهت جلستك، سجّل الدخول للمتابعة» [للتحقق إن كان يُعرض في موضع آخر].
- **مسار إدارة/كونيكت** يُخفى بعد الدخول بنمط `CHAT_ONLY_*` لكن بلا تلميح للمستخدم بكيفية الوصول إليها [للتحقق].

### 5.1 الدخول والتسجيل والتحقق برسالة SMS

**مبدأ:** شاشة واحدة بتبويبين حقيقيين (`role="tablist"`): «دخول» | «حساب جديد».

```
┌──────────────────────────────────┐
│        [شعار]  JassimAI           │
│   ┌──────────┬──────────────┐    │
│   │  دخول    │  حساب جديد   │    │  ← تبويبان (يحفظان ?next=)
│   └──────────┴──────────────┘    │
│  [ المتابعة بحساب Google ]        │  ← فقط إن كان googleSignInConfigured
│  ──────── أو برقم الهاتف ────────  │
```

**تبويب «دخول»:**
1. رقم الهاتف (`+965` افتراضيًا حسب سوق الزائر)، كلمة المرور (إظهار/إخفاء).
2. زر أساسي واحد: «تسجيل الدخول».
3. رابط ثانوي: «رقمي لم يُوثَّق بعد؟ أرسل رمز تحقق» يفتح لوحة سفلية (Sheet) بدل الفقرة الحالية.

**تبويب «حساب جديد» — ثلاث خطوات ظاهرة (شريط 1 ← 2 ← 3):**

| الخطوة | المحتوى | الزر |
|---|---|---|
| 1. بياناتك | الاسم، الدولة (مُحدِّد واحد يحدد الدولة ورمز الهاتف معًا)، رقم الهاتف | «أرسل رمز التحقق» |
| 2. تحقق | «أرسلنا رمزًا إلى `+965 ••• 1234`» ← 6 خانات (`input-otp` الموجود) ← عدّاد «إعادة الإرسال بعد 00:30» ← «تعديل الرقم» | «تحقق» (يُفعَّل عند اكتمال 6 أرقام) |
| 3. كلمة المرور | كلمة المرور + التأكيد + الموافقة على الشروط (نص `TermsAcknowledgementText` كما هو) | «إنشاء الحساب» |

**الأخطاء:** تحت كل حقل (`aria-describedby`)، وملخص خطأ عام بـ`role="alert"` يُزال عند التعديل. رسالة الإرسال تبقى محايدة كما هي («إذا كان الرقم صالحًا…») ولا تكشف وجود الحساب.
**القياسات:** حقول بارتفاع 48px، أزرار 48px، `inputMode="tel"` للهاتف و`"numeric"` للرمز.
**نقطة للمالك:** عدّاد إعادة الإرسال تجميلي في الواجهة فقط؛ الحماية الفعلية من الإساءة تبقى في الخادم.

### 5.2 أول تجربة للمستخدم داخل المحادثة

**استبدال تهيئة 3 شاشات (سلة/كمية) بتجربة محادثية:**

```
┌──────────────────────────────────┐
│  مرحبًا، أنا جاسم 👋              │
│  اكتب ما تريد وسأتولى الباقي      │
│                                  │
│  [ أبحث عن منتج ]  [ أبيع غرضًا ] │  ← شرائح اقتراح تملأ مربع الكتابة فقط
│  [ أتابع طلبًا ]   [ أربط متجري ] │     ولا ترسل شيئًا ولا تنفّذ
│                                  │
│ ┌──────────────────────────────┐ │
│ │ اكتب رسالتك…           [إرسال]│ │
│ └──────────────────────────────┘ │
│ جاسم وسيط؛ البائع هو من يحدد      │
│ السعر ويظهر الإجمالي قبل التأكيد  │
└──────────────────────────────────┘
```

- **الضيف:** يستطيع الكتابة مباشرة (يوجد مسار `GuestHandoff` في `Ai.tsx`). يظهر طلب الدخول فقط عند أول إجراء يتطلب حسابًا، **داخل المحادثة** كبطاقة، ويعود المستخدم لنفس الرسالة بعد الدخول.
- **شرائح الاقتراح:** نصوص ثابتة من الواجهة تُدرج في مربع الكتابة ولا تُرسل تلقائيًا (القرار للمستخدم).
- **حذف الأرقام والادعاءات:** لا «توصيل خلال…» ولا «متاح في كل الدول».
- **التهيئة:** تبقى قابلة للتخطي بزر ≥ 44px، وتُحفظ بالمفتاح نفسه `bdinar-onboarded`.

### 5.3 بطاقات المنتجات الذكية

**مبدأ:** القسم الذي لا يرسله الخادم لا يُرسم، ولا قيم افتراضية، وإجمالي من `card.quote` فقط.

```
┌─────────────────────────────────┐
│ [صورة]   اسم المنتج              │
│          البائع: اسم حقيقي        │  ← «بائع فرد» أو «نشاط موثّق» (فقط عند verified:true)
│  الخيارات:  ○ الحجم  ○ اللون     │
│  ────────────────────────────── │
│  الإجمالي  17.900 د.ك            │  ← كما أرسله الخادم
│  تقديري — يؤكده المتجر           │  ← 13px بجانب الرقم عند final:false
│  حسب نظام المتجر · تحقق 10:24    │  ← فقط عند وجود source
│  [  مراجعة الطلب  ]  (ذهبي واحد) │  ← يفتح مراجعة، لا ينفّذ
└─────────────────────────────────┘
```

- **حالات:** تحميل (هيكل)، فارغ، غير متوفر، خطأ، قديمة («قديمة — حدّثها»).
- **زر ذهبي واحد** لكل بطاقة، وبقية الأزرار ثانوية.
- **سيارات:** «احجز تجربة قيادة» دون سلة.
- **عرض 320px:** عمود واحد، المعارض تمرّر أفقيًا داخليًا فقط.
- **حركة:** تحديث البطاقة في مكانها عند `revision` أعلى مع احترام `prefers-reduced-motion`.

```
│ يتم وفق شروط المتجر.                 │
│                                     │

```

**الحالات بعد الضغط:**

| الحالة | العرض |
|---|---|
| جارٍ الإرسال | الزر معطّل مع «جارٍ الإرسال للمتجر…» |
| `EXECUTED` | «أكّد نظام المتجر استلام طلبك» + سطر «وفق شروط المتجر» (النص الحالي يبقى) |
| ألغِي | «أُلغي؛ لم يُرسل شيء إلى المتجر» |
| فشل/مرفوض | رسالة الرفض الموجودة، مع «لا تعتبره تم» وزر «حاول لاحقًا» |
| انتهت المهلة | زر التأكيد معطّل برسالة «انتهت صلاحية الطلب، اطلب من جاسم من جديد» |

**قواعد:** لا يظهر «تم» إلا بعد `EXECUTED`؛ التركيز ينتقل إلى رسالة الحالة بعد الضغط؛ بيانات القراءة تحمل وسم «كما أرسلها المتجر، وليست تأكيدًا من جاسم» وتُعرض كجدول عربي بدل JSON الخام.

## 6. طلبات للمالك (خارج نطاقي — لن أنفذها)

1. **أسماء حقول بطاقة كونيكت:** قاموس عربي لأسماء الحقول (`arguments.*`) يأتي من العقد (`label` لكل حقل) بدل التخمين في الواجهة. يحتاج تعديلًا في `lib/api-spec` ثم codegen.
2. **عدّاد إعادة إرسال SMS:** قيمة `retryAfterSeconds` من الخادم في رد `RequestPhoneVerificationChallenge` ليكون العدّاد حقيقيًا لا تقديريًا.
3. **«نسيت كلمة المرور»:** هل المسار موجود في الخادم؟ إن لا، فالقرار قرار منتج.
4. **سبب انتهاء الجلسة:** حقل يميز «لم يسجل دخولًا» عن «انتهت الجلسة» لعرض رسالة مناسبة.

## 7. خطة المرحلة ب (بعد إعلان «اكتمل الإطلاق»)

كل بند في فرع مستقل `google/ui-<اسم>`، بعد إعادة الأساس على الفرع الجديد:

| 1 | `google/ui-auth` | 1، 6، 7، 8 (+ نصوص 9) |

**شروط كل فرع قبل العرض:** `pnpm install --frozen-lockfile` ثم `pnpm run typecheck` ثم `pnpm --filter @workspace/dinar run build` ثم اختبارات الواجهة المتأثرة على قاعدة محلية فقط، ثم معاينة على development ولقطات جوال/سطح مكتب. **اختبارات الواجهة الحالية كثيرة** (`artifacts/dinar/test/*`) وتعتمد على `data-testid`، فلا تُغيَّر معرّفاتها ولا يُعدَّل أي اختبار ليمرّ.

## 8. ما لم يُختبر

لم أشغّل الواجهة ولا الاختبارات ولا أي أداة تباين أو قارئ شاشة؛ كل ما ورد استنتاج من قراءة الكود. وسيُراجَع هذا التقرير بعد قراءة بقية الملفات وبعد استقرار نسخة الإطلاق.
