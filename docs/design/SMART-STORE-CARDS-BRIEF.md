# موجز تنفيذ: «البطاقات المتجرية الذكية» داخل محادثة جاسم

> موجّه إلى فريق/وكيل Google المكلّف بالتطوير البصري. اقرأه كاملًا قبل كتابة أي سطر.
> المالك: صاحب JassimAI. المراجِع التقني قبل أي دمج: Claude (مراجعة كود + أمان + اختبارات).

---

## 1. الفكرة في جملة واحدة

**كل بطاقة في المحادثة هي موقع متجر مصغّر كامل يعمل داخل الرسالة، وجاسم هو من يقوده.**

المستخدم لا يغادر المحادثة. يكتب «أريد ملابس رسمية للمكتب بحدود 30 د.ك» أو «برجر دجاج مع جبن إضافي»،
فيرد جاسم ببطاقة تتصرف كموقع حقيقي: رأس بهوية المتجر، تبويبات أقسام، معرض صور، شبكة منتجات،
اختيار لون/مقاس/حجم/إضافات، تنسيق إطلالة أو صندوق هدية، سلة، ومراجعة قبل الشراء — كل ذلك داخل فقاعة واحدة،
ومتصل بذكاء جاسم: البطاقة تتغير حين يكتب المستخدم «أغمق شوي» أو «أرخص» أو «بدون مخلل»،
وجاسم يتغير حين يضغط المستخدم داخل البطاقة.

**البطاقة ليست صورة ولا قالبًا ثابتًا؛ هي واجهة حيّة لبيانات المتجر الحقيقية التي يرسلها الخادم.**

## 2. ما الذي تبنيه بالضبط (النطاق)

تبني **الواجهة الأمامية فقط** في `artifacts/dinar` (React 18 + Vite + Tailwind + Radix + framer-motion + embla-carousel، كلها موجودة مسبقًا).
الخادم وعقد البيانات والأمان والدفع من مسؤوليتنا (القسم 6). تعمل على بيانات تجريبية (fixtures) تطابق العقد حرفيًا حتى نربطها.

### 2.1 هيكل البطاقة الموحّد `SmartStoreCard`

بطاقة واحدة قابلة للتكيّف، لا مكوّن منفصل لكل نشاط. تتكوّن من «أقسام» يرسلها الخادم ويعرضها المكوّن بالترتيب:

| القسم (`section.kind`) | ماذا يعرض | مثال من الصور |
|---|---|---|
| `STORE_HEADER` | اسم المتجر الحقيقي، شعاره، شارة «ممول» إن وُجدت، مفضلة، فلاتر | «بوتيك الأزياء الرجالية» |
| `UNDERSTOOD_REQUEST` | شرائح «فهمت طلبك» قابلة للحذف/التعديل | «ملابس رجالية ✓ تجربة قياس ✓» |
| `CATEGORY_TABS` | تبويبات أقسام المتجر | بدلات، قمصان، أحذية… |
| `HERO_GALLERY` | معرض صور/فيديو مع تكبير ومؤشر صفحات | رفوف الملابس، صورة الكنبة |
| `PRODUCT_GRID` | شبكة/شريط منتجات بسعر وزر إضافة | جاكيت 17.900 د.ك |
| `PRODUCT_DETAIL` | منتج واحد: عنوان، وصف، تقييم (إن وُجد)، سعر | فستان سهرة، كنبة |
| `VARIANT_PICKER` | لون، مقاس، حجم، قماش، كمية | S M L XL، ألوان دائرية |
| `CUSTOMIZER` | خيارات مع أسعار إضافية (اختيار واحد/متعدد) | جبن إضافي +0.350 |
| `BUNDLE_BUILDER` | تجميع عناصر: إطلالة، صندوق هدية، تجميعة حاسوب | «إطلالتك المختارة» |
| `SPECS` | أبعاد ومواصفات | عرض 220 سم، عمق 90 سم |
| `POLICIES` | توصيل، ضمان، إرجاع، دفع — **فقط ما يرسله الخادم** | «إرجاع خلال 14 يوم» |
| `RECOMMENDATIONS` | «مناسب لك»/منتجات مشابهة | غرفة معاصرة/كلاسيكية |
| `SUMMARY_BAR` | الإجمالي + زر الإجراء الرئيسي | «الإجمالي 4.250 د.ك — إضافة إلى السلة» |
| `MEDIA_3D` | معاينة ثلاثية الأبعاد (المستوى 2) | «عرض 3D» |
| `TRY_ON` / `AR` | تجربة/واقع معزز (المستوى 2) | «جرّب على صورتي» |

القاعدة: **قسم لا يرسله الخادم لا يُرسم.** لا قيم افتراضية، لا نصوص تعبئة، لا تقييمات وهمية.

### 2.2 قوالب حسب نوع النشاط (ترتيب أقسام فقط — نفس المكوّن)

- **أزياء:** HEADER → UNDERSTOOD → TABS → GALLERY(رفوف) → GRID → BUNDLE(إطلالة) → VARIANT(مقاس/لون) → SUMMARY. شريط خطوات: الرفوف › التنسيق › المقاس › السلة.
- **مطاعم:** HEADER → GALLERY(الوجبة) → DETAIL → VARIANT(الحجم) → CUSTOMIZER(تخصيص) → CUSTOMIZER(إضافات) → كمية → SUMMARY. نمط «غامر» اختياري (الصورة 15) **بشرط** وجود نص مرئي لكل زر.
- **أثاث وديكور:** GALLERY(360/تكبير) → DETAIL → VARIANT(لون/قماش) → SPECS(أبعاد) → POLICIES → RECOMMENDATIONS(أنماط الغرف) → SUMMARY ("شراء الآن" + سلة).
- **فساتين ومناسبات:** DETAIL جانبي مع صورة كبيرة → VARIANT(لون/مقاس/دليل المقاسات) → GRID(مشابه) → BUNDLE(تنسيق الإطلالة) → SUMMARY.
- **إكسسوارات/ساعات/نظارات:** GALLERY + GRID جانبي + SUMMARY؛ «عرض على المعصم/الوجه» = المستوى 2.
- **هدايا:** BUNDLE_BUILDER(صندوق: ورد، شوكولاتة، عطر، دمية، بطاقة) + VARIANT(لون الصندوق) + SUMMARY.
- **إلكترونيات/تجميع حاسوب:** BUNDLE_BUILDER(معالج، كرت، ذاكرة، تخزين، مزود طاقة) + شارة توافق **من الخادم فقط** + SUMMARY.
- **سيارات:** GALLERY + VARIANT(لون/جنوط/داخلية) + SPECS. الإجراء الرئيسي **«احجز تجربة قيادة» أو «اطلب عرض سعر»** — لا سلة.
- **شبكة الفئات** داخل المحادثة (الصورة 16) حين يكون الطلب عامًا.

### 2.3 الذكاء داخل البطاقة (ما يجعلها ليست موقعًا عاديًا)

1. **ثنائي الاتجاه:** كل تفاعل داخل البطاقة يُرسل حدثًا منظّمًا (القسم 5) ولا يُرسل نصًا حرًا نيابةً عن المستخدم. ما يكتبه المستخدم في المحادثة («أريده أزرق») يعيد الخادم بسببه إرسال البطاقة نفسها محدّثة (نفس `cardId`، `revision` أعلى) — تُحدَّث في مكانها بحركة ناعمة، لا بطاقة جديدة.
2. **«فهمت طلبك»:** شرائح من الخادم؛ الضغط × يرسل حدث `REFINE_REMOVE` فيعاد ترتيب النتائج.
3. **الإجمالي الحي:** أثناء الاختيار يعرض المكوّن **تقديرًا** محسوبًا من أسعار الخادم نفسها مع وسم صغير «تقديري»، ثم يستبدله فور وصول `quote` من الخادم. **السعر النهائي دائمًا من الخادم.**
4. **حالة لكل شيء:** تحميل (skeleton)، فارغ، غير متوفر، خطأ، منتهي الصلاحية («تغيّر المخزون؛ حدّثنا البطاقة»).
5. **مصدر الحقيقة ظاهر:** سطر صغير «حسب نظام المتجر — تم التحقق 10:24» حين تأتي البيانات من نظام المتجر الموصول.

## 3. الهوية البصرية

- **وضعان كاملان:** داكن (كحلي عميق `#0A1A3F` تقريبًا + موجات زرقاء مضيئة) وفاتح (أبيض/أزرق فاتح) — كلاهما بالذهبي للأزرار الأساسية والحواف المضيئة. استخدم متغيرات الألوان الموجودة في `src/index.css` ووسّعها؛ لا ألوان مكتوبة يدويًا داخل المكوّنات.
- **زجاج ناعم:** خلفيات شبه شفافة، حواف 1px مضيئة، زوايا كبيرة (16–24px)، ظلال خفيفة.
- **الذهبي** للإجراء الرئيسي فقط (زر واحد ذهبي في كل بطاقة).
- **التميمة:** الروبوت «J» — هوية واحدة للمساعد في كل مكان. الاسم المعروض: «جاسم» / «JassimAI» بتهجئة واحدة ثابتة.
- **الحركة:** framer-motion؛ دخول البطاقة، تبديل الصور، اختيار الخيار (توهج ذهبي + علامة ✓). احترم `prefers-reduced-motion` إلزاميًا.
- **العربية أولًا و RTL كامل:** الأسهم والمعارض والسحب تنعكس. الأرقام: الدينار الكويتي 3 منازل عشرية (`17.900 د.ك`)، الدولار منزلتان (`$10.00`)؛ استخدم دوال التنسيق الموجودة ولا تكتب الأرقام داخل النصوص.

## 4. ممنوعات قاطعة (أي مخالفة = رفض الدمج)

1. **لا اختلاق بيانات:** لا تقييمات، لا «ضمان سنتين»، لا «توصيل خلال 3 أيام»، لا «متاح في جميع الدول»، لا شعارات وسائل دفع — إلا إن جاءت في بيانات الخادم.
2. **لا صور مولّدة على أنها المنتج:** صور المنتج من المتجر فقط؛ أي صورة توضيحية تحمل وسم «صورة توضيحية».
3. **لا نجاح بلا إيصال:** لا «تم الطلب»، لا «تم تفعيل اشتراكك»، لا احتفال — إلا بعد حالة مؤكدة من الخادم. صفحة الدفع جاهزة ≠ دفع تم.
4. **لا حساب نهائي في المتصفح:** الإجمالي النهائي والرسوم والعملة من الخادم؛ أي قيمة يرسلها المتصفح يتجاهلها الخادم أصلًا.
5. **لا كتابة مباشرة:** «شراء الآن» و«إتمام الشراء» و«احجز» تفتح **مراجعة** بإجمالي الخادم ثم بطاقة تأكيد؛ لا شيء يُنفّذ بضغطة واحدة.
6. **اسم المتجر الحقيقي دائمًا** — لا «مطعم جاسم» إلا إن كان هذا اسم النشاط فعلًا. جاسم وسيط، لا البائع.
7. **لا أسرار ولا مفاتيح** في الكود أو الإعدادات، ولا بيانات عملاء حقيقية في البيانات التجريبية.
8. **لا تلمس:** `artifacts/api-server`، `lib/db`، `lib/api-spec`، ملفات الهجرة، الدفع، العمولة، الصلاحيات، المصادقة. الواجهة فقط.
9. **لا أزرار أيقونة بلا اسم:** كل زر له نص ظاهر أو `aria-label` عربي.
10. **لا مكتبات ثقيلة أو مدفوعة دون موافقة:** المسموح الآن: الموجود + `@google/model-viewer` (تحميل كسول للمستوى 2). مكوّنات Magic UI / Aceternity / React Bits تُنسخ عنصرًا عنصرًا مع ذكر الترخيص (MIT فقط) في رسالة الالتزام، ولا شيء من نسخها المدفوعة.

## 5. عقد البيانات (ما يرسله الخادم وما ترسله البطاقة)

ابنِ على هذه الأنواع حرفيًا (ضعها في `src/features/ai/smart-store/types.ts` مع مخطط zod مطابق). الخادم سيرسلها لاحقًا ضمن حمولة المحادثة؛ الآن استخدم fixtures.

```ts
type Money = { minor: number; currency: string; scale: number; label: string }; // label منسّق من الخادم
type Media = { url: string; alt: string; kind: "IMAGE" | "VIDEO" | "MODEL_3D"; illustrative?: boolean };

type SmartStoreCard = {
  cardId: string;
  revision: number;                       // تحديث في المكان حين يزيد
  vertical: "FASHION" | "FOOD" | "FURNITURE" | "OCCASION" | "ACCESSORIES" | "GIFTS" | "ELECTRONICS" | "VEHICLES" | "GENERAL";
  store: { name: string; logoUrl?: string; sponsored: boolean; verified: boolean;
           mode: "SELL_INSIDE_JASSIM" | "BUY_ON_MERCHANT_WEBSITE" | "MERCHANT_SYSTEM" };
  source?: { kind: "MERCHANT_SYSTEM"; checkedAt: string };   // يظهر «حسب نظام المتجر — تم التحقق …»
  sections: Section[];                    // تُرسم بالترتيب، وما لا يُرسل لا يُرسم
  primaryAction: { kind: "ADD_TO_CART" | "REVIEW_ORDER" | "REQUEST_QUOTE" | "BOOK_TEST_DRIVE" | "OPEN_MERCHANT_SITE"; label: string };
  quote?: { total: Money; lines: { label: string; amount: Money }[]; final: boolean; expiresAt?: string };
  status: "READY" | "LOADING" | "STALE" | "UNAVAILABLE" | "ERROR";
  notice?: string;
};

type Section =
  | { kind: "UNDERSTOOD_REQUEST"; chips: { id: string; label: string }[] }
  | { kind: "CATEGORY_TABS"; tabs: { id: string; label: string; selected: boolean }[] }
  | { kind: "HERO_GALLERY"; media: Media[] }
  | { kind: "PRODUCT_GRID"; products: { id: string; title: string; price: Money; media: Media; available: boolean; selected?: boolean; swatches?: string[] }[] }
  | { kind: "PRODUCT_DETAIL"; productId: string; title: string; subtitle?: string; price: Money; rating?: { value: number; count: number }; media: Media[] }
  | { kind: "VARIANT_PICKER"; groupId: string; label: string; style: "SWATCH" | "CHIP" | "SIZE" | "STEPPER";
      options: { id: string; label: string; color?: string; price?: Money; delta?: Money; available: boolean; selected: boolean }[] }
  | { kind: "CUSTOMIZER"; groupId: string; label: string; multi: boolean; options: { id: string; label: string; media?: Media; delta?: Money; selected: boolean }[] }
  | { kind: "BUNDLE_BUILDER"; label: string; slots: { slotId: string; label: string; item?: { id: string; title: string; price: Money; media: Media } }[];
      compatibility?: { status: "COMPATIBLE" | "INCOMPATIBLE" | "NOT_VERIFIED"; note?: string } }
  | { kind: "SPECS"; rows: { label: string; value: string }[] }
  | { kind: "POLICIES"; items: { icon: "DELIVERY" | "WARRANTY" | "RETURNS" | "PAYMENT"; label: string }[] }
  | { kind: "RECOMMENDATIONS"; label: string; items: { id: string; title: string; media: Media }[] }
  | { kind: "MEDIA_3D"; model: Media; arAvailable: boolean }
  | { kind: "TRY_ON"; available: false; reason: string }; // المستوى 2 — يظهر معطّلًا بسبب واضح الآن

// ما ترسله البطاقة (أحداث فقط؛ لا نص حر ولا أسعار):
type CardEvent =
  | { type: "SELECT_TAB"; cardId: string; revision: number; tabId: string }
  | { type: "SELECT_PRODUCT"; cardId: string; revision: number; productId: string }
  | { type: "SELECT_OPTION"; cardId: string; revision: number; groupId: string; optionId: string; selected: boolean }
  | { type: "SET_QUANTITY"; cardId: string; revision: number; productId: string; quantity: number }
  | { type: "FILL_SLOT"; cardId: string; revision: number; slotId: string; productId: string }
  | { type: "REFINE_REMOVE"; cardId: string; revision: number; chipId: string }
  | { type: "PRIMARY_ACTION"; cardId: string; revision: number }
  | { type: "FAVORITE"; cardId: string; productId: string; on: boolean }
  | { type: "SHARE"; cardId: string; productId: string };          // رابط عام للمنتج فقط
```

- أرسل الأحداث عبر دالة واحدة `onCardEvent(event)` تُمرَّر للمكوّن (سنربطها نحن بالخادم). في الوضع التجريبي: محاكٍ محلي يعيد بطاقة بـ `revision + 1`.
- البطاقات القائمة اليوم في `src/features/ai/CommercialSurface.tsx` و`commercial-types.ts` تبقى تعمل؛ `SmartStoreCard` مكوّن جديد بجوارها.

## 6. ما نبنيه نحن (للعلم، لا تنفّذه)

- إصدار `SmartStoreCard` من الخادم من بيانات المتجر (داخل جاسم أو عبر Jassim Connect).
- استقبال `CardEvent`، إعادة حساب `quote` النهائي، المخزون، التوافق.
- الإجراءات: سلة جاسم ومراجعة الطلب، أو رابط موقع التاجر، أو بطاقة تأكيد لنظام التاجر (موجودة: `/api/connect/action-confirmations/:id/confirm`)، والدفع عبر Whop.
- الاشتراكات: بطاقة الدفع موجودة؛ تحسينها البصري ضمن هذا العمل مسموح **بالالتزام بالقسم 7**.

## 7. شاشات محددة يجب إصلاحها أثناء التصميم

**بطاقة الاشتراك (الصورتان 1 و19):** لا تظهر «تم تفعيل اشتراكك بنجاح» إلا عند `paid: true` من `GET /api/business/subscription-checkout/:id`؛ قبلها «بانتظار تأكيد Whop». احذف «متاح في جميع الدول». أضف ملاحظة الضريبة (نصها يأتي من الخادم `taxNote`). المزايا = ما يرسله الخادم فقط. شعارات الدفع تُحذف. «إلغاء التجديد» يستدعي `POST /api/business/subscription/cancel` ويعرض «طُلب إيقاف التجديد من Whop» لا «تم الإلغاء». «عرض الفاتورة» يُخفى حتى نوفر مصدرها.

**تسجيل الدخول (اعتمد تصميم الصورة 5 + تسميات الشريط الجانبي من الصورة 4):** نفس تدفق المصادقة الحالي (تحقق الهاتف ثم كلمة المرور) دون تغيير منطق؛ رمز الدولة الافتراضي حسب سوق الزائر لا +965 ثابتًا؛ «نسيت كلمة المرور» و«تذكرني» تُعرض فقط إن كانت الميزة موجودة في الكود؛ لا شريط خطأ أحمر دائم على صفحة الدخول.

## 8. المستويات (ابنِ المستوى 1 كاملًا قبل أي شيء من المستوى 2)

**المستوى 1 — مطلوب كاملًا الآن:** `SmartStoreCard` بكل الأقسام عدا `MEDIA_3D/TRY_ON/AR`؛ القوالب التسعة في 2.2 كبيانات تجريبية؛ الوضعان الداكن والفاتح؛ التحديث في المكان؛ الإجمالي التقديري ثم النهائي؛ كل الحالات؛ شبكة الفئات؛ لوحة السلة المصغرة؛ تحسين بطاقة الاشتراك وشاشة الدخول.

**المستوى 2 — لاحقًا بقرار منفصل من المالك:** `MEDIA_3D` عبر model-viewer (تحميل كسول، يُخفى إن لم يوجد نموذج)؛ AR بمقاس حقيقي فقط (لا منزلق يكبّر بحرية)؛ تجربة القياس على الصورة/الوجه — **تتطلب موافقة صريحة، معالجة على الجهاز، عدم التخزين، ووسم «تقريبي»**؛ قياسات الجسم بمرجع جدول مقاسات المتجر.

## 9. الجودة المطلوبة

- يعمل من 320px عرضًا حتى سطح المكتب؛ البطاقة لا تتجاوز عرض الفقاعة ولا تسبب تمريرًا أفقيًا للصفحة (التمرير الأفقي داخل المعارض فقط).
- لوحة المفاتيح: كل خيار قابل للوصول والاختيار بالأسهم/Enter، تركيز ظاهر.
- التباين WCAG AA (انتبه للذهبي على الأزرق والأبيض).
- الأداء: الصور كسولة بأحجام متعددة، لا أكثر من 60KB JS إضافي مضغوط للمستوى 1، لا اهتزاز تخطيط عند التحميل.
- اختبارات: Vitest للمنطق (التقدير، تطبيق الأحداث في المحاكي) + Playwright لرحلة واحدة لكل قالب في الوضعين، بعرضي 390 و1280.
- لا تغيير على اختبارات قائمة لجعلها تنجح.

## 10. طريقة العمل والتسليم

- فرع مستقل من `claude/jassim-connect-universal-engine` باسم `google/smart-store-cards`. لا دمج، لا نشر، لا تعديل `main`.
- التزامات صغيرة واضحة، كل التزام يذكر ما تغيّر ولماذا.
- عند التسليم: قائمة بما بُني مقابل كل بند في الأقسام 2 و7 و8، لقطات شاشة للقوالب في الوضعين وعلى الهاتف وسطح المكتب، ونتائج `pnpm run typecheck` و`pnpm --filter @workspace/dinar run build` والاختبارات.
- بعدها يراجع Claude: الالتزام بالممنوعات (القسم 4)، مطابقة العقد (القسم 5)، الأمان، إمكانية الوصول، الأداء، والاختبارات — ثم يقرر المالك الدمج.
