## 2. ما يجب أن يبقى في مصدر Railway

يعتمد التطبيق على monorepo، وليس على حزمة منفردة. تشمل الملفات اللازمة للتجهيز المحلي والبناء:

- `artifacts/api-server/` و`artifacts/dinar/`.
- حزم `lib/*` المستخدمة من تطبيق الواجهة والخادم، بما فيها `lib/db` وبيانات Drizzle الوصفية.
- `package.json` و`pnpm-lock.yaml` و`pnpm-workspace.yaml` وملفات TypeScript الجذرية.
- ملفات ترحيلات Drizzle من `0000` إلى `0039`، و`lib/db/drizzle/meta/_journal.json`؛ العدد المرصود 40 ملف ترحيل.
- وثائق الإصدار وR3 التي يوافق عليها المالك بعد مراجعة الخصوصية؛ هي توثيق وليست متطلبات تشغيل.

خطة الإطلاق الرئيسية الأحدث تحدد مستقبلاً خدمة تطبيق واحدة باسم `dinar-app` لتقديم `/api/*` والواجهة من الأصل نفسه، مع PostgreSQL وbucket مستقلين لكل بيئة. أمر البناء المقترح فيها:

```sh
pnpm install --frozen-lockfile
pnpm --filter @workspace/api-server run build
pnpm --filter @workspace/dinar run build
```

وأمر التشغيل المقترح من مجلد حزمة API:

```sh
pnpm --filter @workspace/api-server run start
```

لكن هذا **ليس جاهزاً للنشر**: الخطة تسجل أن API لا يقدّم ملفات الواجهة بعد؛ `T-G2-02` مطلوب لخدمة الواجهة من API، و`T-G1-01` مطلوب لمشغل ترحيلات محمي، و`T-G2-03` مطلوب لإعداد Railway-as-code. وتشترط الخطة `Node 24` و`/api/readyz`، وقاعدة PostgreSQL جديدة، وعدم استخدام قاعدة التطوير. هذه مواصفات مستقبلية وليست إذناً لإنشاء أو تشغيل أي مورد.

## 3. إجراء تصدير معزول قابل للتراجع — لا ينفذ قبل الإبطال والموافقة

يُجرى الإجراء التالي في مجلد مؤقت منفصل، ولا يغيّر المستودع الأصلي أو فروع النسخ الاحتياطية:

1. ينتظر المنفذ انتهاء جلسة Claude، ثم يسجل SHA الحالي وحالة الشجرة والمراجع للقراءة فقط. إذا تغيّر HEAD أو بقيت تعديلات متزامنة، يتوقف ويعيد مراجعة خط الأساس.
2. بعد تأكيد إبطال الرمز وموافقة المالك، ينشئ استنساخاً مستقلاً لـ `main` فقط، بلا hardlinks ولا tags:

   ```sh
   git clone --no-local --single-branch --no-tags --branch main \
     /home/runner/workspace /tmp/dinar-pro-clean-export
   ```

3. يتحقق داخل الاستنساخ من أن فرع المصدر هو `main` عند SHA الموافق عليه، وأنه لا توجد tags أو فروع وكيلة يراد نشرها. يحذف **داخل الاستنساخ المؤقت فقط** مرجع التتبع `refs/remotes/origin/main` قبل التنقية، ثم يؤكد أن المرجع المحلي المقصود الوحيد هو `refs/heads/main`. لا ينفذ ذلك في الأصل.
4. ينشئ ملف قواعد مؤقتاً لا يحتوي على الرمز، بل على نمط عام فقط:

   ```text
   regex:github_pat_[A-Za-z0-9_]{40,}==>REDACTED_GITHUB_PAT
   ```

5. يشغّل `git-filter-repo` في الاستنساخ المؤقت على كل التاريخ الذي يصل إليه `main` باستخدام ملف القواعد (`--replace-text`). لا يمرر الرمز الحقيقي إلى أمر أو ملف أو سجل، ولا يغيّر محتوى ملفات التطبيق إلا باستبدال النمط المكتشف. إذا لم تكن الأداة متاحة أو لم تكن نتيجة التصفية واضحة، يتوقف ولا يثبت أداة داخل المشروع ولا يلتف على الحماية.
6. يتحقق أن شجرة العمل في التصدير تطابق مصدر `main` المعتمد، عدا قائمة الاستبعادات المتفق عليها وقيمة النمط المنقحة؛ يفحص محتوى كل blob قابل للوصول وأنماط الأسرار، ثم يحصي المراجع المنقحة. المرجع الذي سيدخل GitHub هو فرع واحد محدد فقط.
7. يبني ويختبر نسخة التصدير في بيئة محلية معزولة، دون أي اتصال حي بمزود AI أو دفع، ودون قاعدة Railway. لا تبدأ اختبارات قاعدة بيانات إلا بعد تصريح مستقل يحدد قاعدة اختبار disposable آمنة.
8. يحفظ سجل نتيجة الفحص والبناء وSHA الجديد في التقرير، دون إخراج قيمة سرية. يظل التصدير المؤقت قابلاً للحذف بعد التحقق؛ يبقى الأصل وفروع Replit والنسخ الاحتياطية دون تغيير.

لم يُنفذ أي بند من خطوات التنقية أو البناء بعد؛ `git-filter-repo` غير موجود في PATH حالياً. يلزم التحقق من الأداة وإصدارها داخل بيئة التصدير عند الموافقة، لا في الأصل.

## 4. أثر إعادة كتابة التاريخ والمراجع الممنوعة

- `git-filter-repo` يغير SHA للالتزامات التي تتأثر بها الشجرة أو يتغير أحد أسلافها؛ لذلك ستختلف SHAs في النسخة النظيفة عن `main` الأصلي، حتى لو بقيت ملفات التطبيق الحالية مطابقة.
- التغيير المقترح محصور في **نسخة التصدير المؤقتة**. لا `reset` ولا `rebase` ولا حذف refs ولا تعديل للنسخة الأصلية أو `gitsafe-backup`.
- يجب استبعاد المراجع السبعة المدرجة في القسم 1 من التصدير، أو تنقيتها في نسخة منفصلة قبل إضافتها بموافقة؛ لا تستخدم `git fetch --all` ولا ترفع كل المراجع أو tags المحلية.
- لا يُسمح بـ force-push أو تجاوز GitHub Push Protection. إذا رفض GitHub التاريخ المنقح، يتوقف العمل وتُراجع النتيجة والسياسة الرسمية بدلاً من تجاوز الحماية.

## 5. GitHub والمزامنة المستقبلية

- تكامل GitHub App المتصل جاهز لطلبات القراءة، ونجح البحث؛ إنشاء المستودع لم يحدث. لم يظهر مستودع `dinar-pro` مطابق يمكن الوصول إليه، لكن ذلك لا يثبت غيابه عن حساب/منظمة أخرى لا يراها الاتصال.
- عند صدور موافقة منفصلة، يُنشأ أو يُعاد استخدام مستودع `dinar-pro` بخصوصية **Private** عبر اتصال المالك، بعد فحص أنه فارغ أو مراجعة محتواه إن كان موجوداً.
- الدفع الأول يجب أن يستخدم مسار Git موثوقاً ومصرحاً به. سر Replit المسمى `GIT_URL` متاح بالاسم في البيئة؛ لم تُقرأ قيمته. لا تُضمّن قيمة اعتماد في remote URL أو أوامر مطبوعة أو سجلات. إنشاء المستودع عبر REST لا يعني أن أول Git push قد تم.
- بعد إنشاء التاريخ النظيف، لا تُدمج فروع `main` أو `replit-agent` أو النسخ الاحتياطية الملوثة في GitHub. للمزامنة، تُنقل تغييرات Replit الجديدة كمراجعة diff/patch إلى clone نظيف مبني على فرع GitHub المنقح، ثم تُفحص وتُبنى وتُسجل كالتزامات جديدة عليه. تُدفع المراجع النظيفة المختارة فقط؛ لا يُجلب التاريخ الملوث إلى clone النشر.

## 6. فحوص المصدر المطلوبة قبل إعلان الجاهزية

لم تُشغّل builds أو tests على التصدير المنقح؛ فهو لم يُنشأ بعد. بعد الموافقة، يجب إثبات ما يلي على **نسخة التصدير نفسها**:

1. فحص أسرار للشجرة والتاريخ وكل المراجع التي ستُنشر، مع إظهار المسار/الالتزام/نوع النمط فقط، دون قيمة الرمز.
2. مراجعة قائمة الملفات وallowlist للأصول؛ إثبات خلو النسخة من قواعد جلسات الأدوات والمرفقات الخاصة والملفات المؤقتة و`.env*` والملف `-` غير المصنف.
3. وجود حزم workspace والـ lockfile وبيانات Drizzle و40 migration متطابقة مع journal.
4. نجاح `pnpm install --frozen-lockfile` ثم build API وVite والأمر الجذري `pnpm run build` و`pnpm run typecheck`.
5. تشغيل اختبارات الأسرار والاختبارات الوحدوية غير المتصلة بمزود أو دفع. تُراجع سكربتات الاختبار قبل تشغيلها لتجنب أي اتصال حي. لا تستخدم مفاتيح DeepSeek أو الدفع أو قاعدة Railway.
6. أي اختبار DB يحتاج قاعدة اختبار منفصلة disposable وتصريحاً منفصلاً؛ لا يستخدم `DINAR_DEV_DATABASE_URL` ولا يغيّر أي قاعدة قائمة.
7. بعد الموافقة على النشر فقط: يطابق SHA فرع GitHub الناتج SHA النسخة المنقحة؛ لا يُدفع أي فرع آخر.

## 7. العوائق والموافقات المنفصلة

العوائق الحالية:

1. المالك لم يؤكد إبطال PAT. يجب إبطاله من إعدادات GitHub وتدويره/إلغاءه من المالك؛ لا نستخدمه ولا نحاول التحقق من صلاحيته.
2. تاريخ `main` ومراجع متعددة تحتوي النمط؛ النشر متوقف حتى تنقية نسخة التصدير ومراجعتها.
3. ملفات `attached_assets/` والملف `-` لم تُعتمد من ناحية الخصوصية أو الحاجة.
4. جلسة Claude كانت لا تزال نشطة عند إعداد الخطة؛ لا تُجرَ عملية Git متزامنة. SHA في تقرير التسليم السابق أقدم من HEAD الحالي ويجب مراجعته بعد استقرار الجلسة.
5. لا توجد بعد نتيجة بناء/اختبارات على التصدير المنقح، ولا يوجد مستودع GitHub منشأ أو SHA بعيد.
6. متطلبات Railway التشغيلية في خطة الإطلاق ما زالت تتضمن أعمالاً برمجية غير منجزة وموافقات منفصلة. هذا التقرير لا يجيز اتصال Railway أو نشر Staging.
