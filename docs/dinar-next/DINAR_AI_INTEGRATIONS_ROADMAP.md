## Recommended sequence

1. **Confirm and freeze baseline.** Use `6b56704`; keep `995d2e5` as the documented source record. Review exact migration release manifest before any deployment.
2. **Owner chooses market and legal scope.** Complete country evidence/counsel/technical/owner readiness. Do not connect commercial providers before this gate.
3. **Provision only staging.** Separate app, private PostgreSQL and Bucket with synthetic data; use the existing Dockerfile and one API replica.
4. **Prove operations.** Migration rehearsal, health/readiness, pool sizing, logs, budgets, database and media backup/restore, cookie/CSRF/CSP and shutdown.
5. **Choose required communications and AI.** Register only approved provider adapters. Confirm SMS readiness requirement. Verify OpenRouter route/privacy and visual analyzer slot; run bounded synthetic acceptance with no paid fallback.
6. **Complete user-facing launch needs.** Account/session/browser checks, public product pages and SEO, device acceptance, policy approval, support and dispute operations.
7. **If commerce requires it, onboard one PSP.** Obtain written local legal/marketplace/settlement approval; sandbox-test the adapter against DINAR's existing financial authorities.
8. **Add optional services only by evidence.** Named Connect platform, map feature, image generator, email/push or error service after usage and privacy review.
9. **Independent Claude review of exact candidate.** Review acceptance, migration order, provider policy, finance, data access and restore proof. Owner alone approves any production release.
