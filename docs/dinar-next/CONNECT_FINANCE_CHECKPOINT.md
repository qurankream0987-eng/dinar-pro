## Implemented authority and state transitions

- `connect/agreements.ts`: independent admin proposal, immutable version/digest, explicit verified owner acceptance, exact displayed-digest comparison, idempotent acceptance evidence. Every commercial term is explicit: percentage or fixed commission, category rates/exclusions, currency, effective interval, attribution/reporting windows, payment/settlement terms, refund policy and rounding. There is no default external 10% rate. Only `SIMULATION_ONLY` agreements execute; unsupported currencies fail closed.
- Attribution reuses `privacy_consent_events` and the existing owned conversation result sets. The default is **untracked**. Only a current accepted agreement, reviewed provider referral template, displayed privacy notice/version and explicit per-link opt-in create an immutable opaque referral. URLs receive only that opaque ID, never the account/conversation/prompt. Withdrawal appends to the existing consent ledger and invalidates prior unconverted attribution even after a later opt-in; existing accounting evidence is retained.
- `connect/finance.ts`: approved integration plus dedicated scoped, hashed bearer credential authenticates incoming conversions. A browser cookie cannot authenticate a conversion. Exact currency and item totals, immutable agreement/transaction snapshots, eligible events, referral scope/consent/window and strict per-transaction sequence are checked before accrual. Identical event IDs/body digests are idempotent; changed bodies and missing predecessors conflict. Concurrent duplicates create one transaction/accrual.
- Root conversion → VERIFIED; matching provider commission approval → APPROVED; independent admin review after the agreed due date → PAYABLE. A provider `COMMISSION_SETTLED` is retained as a **claim**, not proof of received funds. A separately authorized admin reconciliation, with that exact transaction's unused provider claim, creates SIMULATED_SETTLED evidence. All receipts and dashboards explicitly say simulation; actual received real money remains zero in simulation.
- Integer/BigInt calculations in `connect/commission-math.ts` implement accepted percentage/category/fixed rules and cumulative per-item refunds. Partial refunds reduce net earned/approved/payable balances. Historical settlements are not erased; a separate RECOVERY_DUE balance records a clawback. Full refunds/cancellations/chargebacks reverse commission. Provider rejection opens a dispute without silently erasing contractual evidence. Disputes freeze payable balances; independent resolution restores only a supported state or reverses the commission. Commission reversal does not invent a customer refund.
- All accounting/evidence remains append-only. The new migration checks ledger-only appends against the final transaction state at commit and forbids re-earning a REVERSED/REJECTED/PENDING_VERIFICATION transaction or retaining payable funds in DISPUTED state. The previous transaction-evidence trigger now inspects the final header, not an earlier update's `NEW.state`.
- No implicit FX: a conversion in a different agreement currency is refused pending an explicitly accepted rate/capability. No internal order, payment, seller dues or internal marketplace fee authority is invoked.
- Provider settlement IDs are scoped to their actual integration/transaction. Different integrations may legitimately use the same external ID; the same transaction cannot reconcile the claim twice. Foreign referrals and revoked credentials are denied.
