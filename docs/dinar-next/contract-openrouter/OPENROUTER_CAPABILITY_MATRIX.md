## Deployable routing and protected configuration

`src/ai/model-gateway.ts`: deployable OpenRouter routing uses `DINAR_AI_PROVIDER=OPENAI_COMPATIBLE`, base URL `https://openrouter.ai/api/v1`, an exact explicitly approved non-free model and exactly one provider order. Require DATA_COLLECTION=deny, ZDR=true and REQUIRE_PARAMETERS=true. Requests set provider allow_fallbacks=false. The development OPENROUTER alias resolves openrouter/free and is rejected for staging/production. Flags express requested privacy constraints; they do not prove vendor retention behavior, legal terms or actual availability. Remote validation remains BLOCKED.

Primary credential binding: DINAR_AI_API_KEY. For an OPENAI_COMPATIBLE HEAVY slot the current resolver reads **DINAR_AI_FALLBACK_API_KEY**, not DINAR_AI_HEAVY_API_KEY (OR04 independently verifies this). This is a configuration compatibility hazard; do not provision only the latter and claim heavy readiness. Readiness must confirm the actual selected slot without exposing values. OPENROUTER_API_KEY is not the deployable compatible-slot binding. Dedicated vision DINAR_AI_VISION_* maps into an isolated namespace when explicitly configured; no text credential should be copied to vision.

Accounting identity is OPENAI_COMPATIBLE plus exact model, not necessarily OPENROUTER. Configure reviewed versioned prices and cost reservations against the actual accounting identity before activation. Primary, retry, fallback and concurrent vision reservations must fit approved user/global caps; exhausted cap denies new work. Immutable historical finance snapshots are untouched.

`model-turn.ts` registers staging sandbox AI_TEXT only for JO, behind staging environment and master `DINAR_AI_MODEL_FALLBACK`; no production LIVE AI_TEXT registration was established. 22 market configurations do not establish AI activation in all 22 markets. DINAR_LIVE_PROVIDERS_ENABLED=false alone does not disable staging SANDBOX calls. Keep master false; isolated tests additionally block model calls. No provider flags were changed here.

No architectural gap justifies another agent framework. Remaining work is approved model/provider selection, exact protected slot configuration, prices/caps/budget approval, remote capability and privacy validation, and semantic evaluation. Optional upstream token streaming would be a transport extension within the existing engine.
