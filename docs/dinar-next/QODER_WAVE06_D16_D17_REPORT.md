## 4. D17 — المعمارية والضوابط

### 4.1 مصدر واحد للذاكرة

- المصدر الوحيد هو `messages` داخل محادثات `kind = 'AI'` المملوكة للمستخدم، مع موجز مشتق `DERIVED_SUMMARY` في `conversation_summaries`.
- لا جدول رسائل ثانٍ، لا قاعدة ثانية، لا مشغّل ذاكرة مستقل، ولا مزوّد تضمين مدفوع. الموجز **استخلاصي حتمي** (`derivation = 'DETERMINISTIC_EXTRACTIVE'`)، ليس توليدًا بنموذج.
- الذاكرة **ليست سلطة**: لا تمنح تفويضًا ولا موافقة ولا سعرًا ولا حالة؛ قاعدة النظام (`model-turn.ts:245`) تنص أنها نص مقتبس غير موثوق ويجب إعادة التحقق من أي حالة لدى الخادم.

### 4.2 الحدود الثابتة

| الحد | القيمة | الموضع |
|---|---|---|
| نافذة البحث | `LIMIT/OFFSET` مقصوصة إلى 10,000 كحد أقصى وإزاحة غير سالبة | `conversation-memory.ts:191` |
| مهلة الاستعلام | `SET LOCAL statement_timeout = '400ms'` داخل transaction | `conversation-memory.ts:25` |
| طول المقتطف | 320 حرفًا بعد التنقيح والتطبيع | `conversation-memory.ts:23` |
| كتلة سياق الذاكرة | 1200 حرفًا كحد أقصى | `conversation-memory.ts:27` |
| تجديد الموجز | عند 6 رسائل غير مغطاة أو غياب الموجز | `conversation-memory.ts:13` |
| مصدر الموجز | نافذة آخر 12 رسالة × 240 حرفًا، وحد 4000 للموجز | `conversation-memory.ts:15` |
| العرض | آخر ملخصات مرتبة بالأحدث، حالة قديمة موسومة `stale` | `conversation-memory.ts:374` |

### 4.3 عزل الملكية والاستبعاد

- استعلام SQL يربط `messages.conversations.owner_user_id` بالمستخدم المصادق، ويشترط `kind = 'AI'`، ويقصي `metadata.inquiryDelivery` و`metadata.inquiryContent` قبل الفرز والحد.
- أي خطأ في طبقة الذاكرة يُعيد `[]` (تدرّج آمن) ولا يُفشل الدور.
- موظف البائع لا يحصل على ذاكرة المالك: الشرط في `smart-turn.ts:963` يمنع بناء الذاكرة أصلًا لجلسة الموظف.

### 4.4 الإبطال

- حذف رسالة مصدر يُبطل الموجز المشتق.
- حذف كل الرسائل يزيل الموجز بدل تقديمه.
- حذف المحادثة يُسقط الموجز بـcascade.
- «النسيان» يزيل الصف المشتق فقط ولا يمسّ الرسائل المخزّنة.
- زمن حذف لا يُعيد رسالة محذوفة، وإعادة البناء المتزامنة تنتهي بصف واحد.

### 4.5 موضع الذاكرة في الطلب (إصلاح أمني)

كانت النسخة الأولى تُدرج `SERVER_CONVERSATION_MEMORY` داخل رسالة المستخدم نفسها. أثبتت سلسلة D6 أن نصًا قديمًا مقتبسًا يمكن أن يُقرأ كأنه طلب اليوم (بوابة نصية مكتوبة أعادت `SEARCH_INTENT` بدل `PURCHASE_REVIEW`). الإصلاح في `db4c265`: الذاكرة **رسالة system مستقلة** قبل رسالة المستخدم الحالية، مع وسم «untrusted» في مطلع الكتلة (`renderMemoryContext`)، فلا تختلط بتاريخ اليوم ولا تُقرأ كأمر.

### 4.6 لا سطح تصدير أو HTTP

لا مسار HTTP ولا تصدير ملفات لطبقة الذاكرة (اختبار E6)؛ لا وجود لواجهة تقرأ موجز شخص آخر حتى بمعرفة `conversationId` (اختبارات A2/A6).

## 6. قياسات قاعدة البيانات (D17.7)

## 10. نتائج أمنية

1. **[أُصلح] خلط الذاكرة برسالة المستخدم الحالية** (`db4c265`): نص تاريخي مقتبس كان يمكن أن يُقرأ كطلب اليوم. الآن كتلة system منفصلة قبل رسالة المستخدم، مع وسم عدم الثقة، وأثبتت سلسلة D6 زوال الانحدار.
2. **[مُتحقَّق] لا تسرب عبر الملكية**: كل استعلامات البحث/الموجز/النسيان تبدأ من `owner_user_id` المصادق؛ لا مسار بمعرّف محادثة دون ملكية؛ موظف البائع لا يرث ذاكرة المالك؛ الحقن النصي والمحذوف والمستبعد لا يعود.
3. **[مُتحقَّق] تنقيح قبل النموذج**: `redactForModel` يُطبَّق على كل مقتطف؛ اختبار D1 أثبت أن النص المحقون يبقى حرفيًا، واختبار `059c393` أثبت أن الأرقام الشبيهة بالهاتف تُنقَّح حتى داخل نتيجة بحث (سلوك إنتاجي صحيح).
4. **[مُتحقَّق] لا سلطة**: لا مسار من الذاكرة إلى مبلغ/سلة/تفويض (D17.1)، ولا إيصال دفع أو موافقة مزيفة تُعرض كحقيقة (B2/B3/B4)، ولا سطح HTTP/تصدير (E6).
5. **[مفتوح، موثّق] KYC `NOT_SCANNED`**: يبقى مقبولًا شكليًا في `requirementState`؛ يحتاج قرارًا وقرارًا معماريًا من Replit/المالك، ولم يُغيَّر هنا.
6. **[مفتوح، موثّق] تمرين فشل الترحيل والترقية**: غير منفَّذ في هذه الموجة (انظر §5.5).
