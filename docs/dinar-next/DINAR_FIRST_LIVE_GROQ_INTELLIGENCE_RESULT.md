# DINAR — نتيجة بوابة أول تقييم ذكاء حي عبر Groq

**التاريخ:** 2026-10-24  
**الحالة النهائية:** `BLOCKED_FREE_TIER_UNVERIFIED`  
**الفحص المحلي:** `LOCAL_ONLY_VERIFIED`

## الخلاصة

لم يُرسل أي طلب استدلال إلى Groq. لا يمكن إثبات حالة Free Plan أو تعطيل Developer upgrade أو انعدام مسار فوترة لهذا الحساب من وجود المفتاح أو الوثائق العامة. وفق بوابة التنفيذ، أُوقف التقييم الحي قبل أي اتصال استدلال.

لم تُستخدم Railway أو قاعدة بيانات أو خدمة إنتاج، ولم تُجرَ كتابة تطبيق دائمة أو محاولة تفعيل مزوّد أو دفع أو نشر أو push. لم تُقرأ قيمة أي سر أو تُطبع.

## التهيئة والمصدر

- HEAD عند الفحص: `8863595f7f3f3687f993a76bb7a876017ee56f1d` على `main`؛ شجرة العمل نظيفة.
- مسار التقييم يعيد استخدام `createConversationModelGateway` و`interpretWithModel` وعقد `dinarConversationTurn` وZod القائم. لم يُنشأ محرك أو prompt ثانٍ.
- عُثر على السر المخصص `DINAR_BENCH_GROQ_API_KEY` عبر واجهة فحص وجود الأسرار فقط. هذا لا يثبت صلاحية الحساب المجانية ولا حالته التجارية.
- إعداد `groq-free-benchmark.example.json` ما زال يحمل بيانات اعتماد شكلية وجميع موافقات الحساب الأربع `false`. لم تُعدّل هذه القيم.
- المرشح المثبّت هو `openai/gpt-oss-120b` فقط، عبر `CHAT_COMPLETIONS` و`AUTO`؛ لا reasoning setting غير موثق، ولا بديل مدفوع.

## نتائج التحقق الرسمي من Groq

راجعت صفحات Groq الرسمية في 2026-10-24:

- صفحة النماذج تعرض `openai/gpt-oss-120b`. صفحة الأدوات تعرض دعم tool use وJSON mode، لكن لا تعرض دعم الاستدعاء المتوازي. عقد DINAR يمرر أداة DINAR المحلية فقط، ولا يفعّل built-in tools أو web search أو code execution أو MCP.
- صفحة النموذج تعرض أسعار Developer قدرها **$0.15 لكل مليون token إدخال و$0.60 لكل مليون token إخراج**. لذلك فإن السعر الصفري في عقد الاختبار المحلي لا يضمن أن حساب Groq أو مفتاحه سيبقى غير مفوتر.
- صفحة rate limits تحذر من أن الحدود العامة إرشادية، وتوجّه إلى صفحة حدود المؤسسة داخل الحساب لمعرفة القيم الدقيقة. الأرقام العامة المنشورة لا تثبت الخطة الحالية أو المتبقي من حصة هذا الحساب.
- Groq تقول إن بيانات inference لا تُحتفظ بها افتراضياً، لكنها قد تُسجل مؤقتاً لموثوقية المنصة أو مكافحة الإساءة لمدة تصل إلى 30 يوماً؛ بيانات الاستخدام الوصفية تُحتفظ بها دائماً. ZDR متاح من إعدادات الحساب، والبيانات تُخزّن في الولايات المتحدة وفق صفحة البيانات. إعدادات هذا الحساب وقبول المالك لهذه الشروط غير معروفين.

**غير قابل للتحقق من هنا:** Free Plan الفعلية للمؤسسة التي يخصها المفتاح، تعطيل Developer upgrade، تعطيل كل مسار فوترة، الحد الدقيق والمتبقي للحساب، وإعدادات الخصوصية وZDR. لا يُستعاض عن ذلك بجدول عام أو بوجود السر.

## العزل والفحوص المحلية

شُغّل:

```sh
pnpm --filter @workspace/api-server run test:benchmark-guards
```

**النتيجة: 18/18 ناجحة، 0 فشل.** تغطي الفحوص، ضمن أمور أخرى:

- منع نموذج أو نقل أو إعداد أداة غير معتمد، واشتراط موافقات Groq خاصة بالحساب.
- حصر Groq في النموذج المحدد وأربع طلبات كحد أقصى، وتزامن واحد، بلا retries، وميزانية محلية مصرح بها تساوي `$0`.
- رفض تجاوز سقف الطلبات/المدخلات/المخرجات، والتعامل مع المهلة وأخطاء المزوّد والـtool contract.
- تمرير allowlist معزولة لعملية الاختبار؛ قاعدة البيانات تشير إلى منفذ loopback مغلق، ولا تدخل أسرار Railway أو الإنتاج أو التخزين أو الدفع أو المفاتيح التشغيلية في اختبارات الحواجز.
- غياب fallback في عملية benchmark وإزالة متغيرات `DINAR_AI_FALLBACK_*` قبل تحميل مسار runtime.

## الإجراء التالي قبل أي اتصال حي

على المالك مراجعة حساب Groq الذي يخصه `DINAR_BENCH_GROQ_API_KEY` والتأكد بنفسه من:

1. أن الخطة الفعلية Free Plan، وأن Developer upgrade غير مفعّل، ولا يوجد مسار billable يمكن أن يُستخدم.
2. حدود المؤسسة الدقيقة والمتبقية للنموذج من صفحة Limits.
3. سياسة الاحتفاظ والخصوصية وإعدادات ZDR وقبول معالجة البيانات الاصطناعية وفق هذه الشروط.

بعد تحقق ذلك فقط، يسجل المالك موافقاته الأربع في إعداد benchmark المخصص: `groqFreeTierConfirmed`, `groqDeveloperUpgradeDisabledConfirmed`, `groqNoBillablePathConfirmed`, و`groqPrivacyReviewed`. لا تُملأ هذه الموافقات اعتماداً على هذا التقرير أو على جدول أسعار عام. ثم تُراجع خطة التشغيل، ويبقى حد التنفيذ أربع طلبات كحد أقصى، تزامن واحد، بلا retries أو paid fallback، وميزانية مخوّلة `$0`. عند أي التباس، يبقى التقييم متوقفاً.
