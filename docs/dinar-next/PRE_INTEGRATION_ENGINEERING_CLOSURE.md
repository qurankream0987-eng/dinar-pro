## 2. المرحلة 2 — الخصوصية وحقوق المستخدم

**المُعاد استخدامه:** حذف الحساب (`deactivateOwnAccount`) مع إبقاء السجلات المطلوبة، `DATA_RETENTION_POLICY`، تعديل الملف (`PATCH /account/profile`)، ضوابط الذاكرة الشخصية، مشاركة الموقع لمرة واحدة لطرفي الطلب.

**المُنفّذ:** `lib/privacy-rights.ts` (سلطة واحدة للـ API والمحادثة)، `routes/privacy.ts`، جداول `privacy_requests` + `privacy_request_events` (append-only)، `user_privacy_preferences`، `privacy_consent_events` (append-only، trigger).

| الحق | المسار | الضوابط |
|---|---|---|
| الاطلاع | `GET /account/privacy` | بيانات المستخدم فقط + عدّ لكل فئة + التفضيلات + جدول الاحتفاظ |
| التصحيح | `PATCH /account/profile` (الاسم/المدينة/المنطقة)؛ غيرها طلب `CORRECTION` | مراجعة بشرية للهاتف وغيره |
| التصدير | `POST /account/privacy/exports` | إعادة مصادقة بكلمة المرور، 5/ساعة لكل مستخدم، لا يُخزن على الخادم، محدود لكل فئة مع علم `truncated`، لا بيانات للطرف الآخر، الحقول المحجوبة مُعلنة (`withheld`) |
| الحذف | `POST /account/deletion` (قائم) | يُسجّل الآن كطلب `DELETION` مكتمل مع الإبقاء على السجلات المطلوبة |
| سحب الموافقة / التواصل | `GET/PATCH /account/privacy/preferences` | التسويق opt-in لكل قناة؛ رسائل الطلبات والأمان ليست تسويقًا؛ تحكم إصدار (409 عند التقادم)؛ كل تغيير حدث موافقة |
| إذن الموقع | `deviceLocationSharing: ASK_EACH_TIME | DISABLED` | يُفرض على الخادم في `attachTransactionLocation` (403 `LOCATION_SHARING_DISABLED`)؛ الإدخال اليدوي يبقى |

**متبقٍ / قرارات:** مدد الاحتفاظ والأسس القانونية، مهلة الرد، إدراج إحداثيات الجهاز في التصدير (محجوبة حاليًا)، قناة تحقق هوية خارج الحساب لمن فقد الوصول، تصدير الصور، اتفاقيات المعالجين.

## 3. المرحلة 3 — التحكم الفعلي بتكلفة الذكاء الاصطناعي

**المُعاد استخدامه:** دفتر G1 (`ai-usage.ts`): حجز ذري، idempotency، تسوية/تحرير/انتهاء، حارس عالمي للطلبات/الرموز.

**المُنفّذ:** `lib/ai-spend.ts` + جداول `ai_model_prices` (إصدارات بتاريخ سريان)، `ai_spend_holds`، `ai_spend_counters`، `ai_cost_events` (صف لكل نداء)، `ai_billing_reconciliations`. سياسة `aiUsage.spend` (اختيارية في الصفوف القديمة).

- **وحدات صحيحة بالميكرو** (1 USD = 1,000,000)، حساب BigInt، تقريب للأعلى.
- **لكل نداء:** المزود والنموذج الفعليان، النوع `PRIMARY/RETRY/FALLBACK/CORRECTION`، النتيجة، رموز الدخل/المخزّنة/الخرج، وحدات الصور وثواني الصوت، معرف طلب المزود.
- **تقدير مقابل نهائي:** `ESTIMATED` حتى المطابقة، `FINAL` بعدها، `UNPRICED` عند غياب سعر/وحدة/عملة مطابقة — **يُحمّل كامل مبلغ الحجز، ولا يُعد صفرًا أبدًا**، ويُعدّ في `unpriced_calls`.
- **الاستخدام غير المُبلغ:** يُسعّر من تقدير الرموز كأنه خرج (الأغلى)؛ الصوت دون مدة مُبلغة = `UNPRICED`.
- **حجوزات متزامنة آمنة:** تحديث شرطي لكل نطاق (عالمي → خطة → حساب) في نفس معاملة حصة الطلبات؛ الرفض يُلغي الاثنين.
- **سقوف نقدية:** عالمي لكل فترة، لكل حساب حسب الخطة، ولكل خطة إجمالًا. في production/staging أو `DINAR_AI_SPEND_REQUIRED=true` غياب السقف العالمي = **لا نداء مدفوع** (`SPEND_BUDGET_UNCONFIGURED`). `unpricedModel: REFUSE` يرفض نموذجًا بلا سعر قبل النداء.
- **أسعار الاختبار:** `TEST_PLACEHOLDER` تُتجاهل خارج التطوير/الاختبار.
- **المطابقة:** `reconcileProviderBilling` / `AiBillingSource`: تطابق بمعرف الطلب، تصحيح العدادات بالفرق، `DISCREPANCY` للبنود غير المعروفة، `INCOMPLETE` للنداءات غير المغطاة، إعادة التشغيل آمنة؛ مصدر غير متاح يُعلن كذلك.
- **كل المسارات:** محادثة مسجلة، زائر، تحسين النص التسويقي، صور البائع، مراجعة صور المنصة، الذاكرة في الخلفية، الصوت. الحجوزات المهجورة تُحمّل نداءً مجهولًا بكامل الحجز.

**متبقٍ / قرارات:** اختيار المزود والنموذج، أسعار رسمية مؤرخة، السقف العالمي والسقوف لكل خطة/حساب، مبالغ الحجز (القيم الحالية placeholders هندسية)، مصدر فواتير المزود، العملة.

## 4. المرحلة 4 — اشتراكات Free / Go / Pro

**المُعاد استخدامه:** منتجات `DINAR_BUSINESS` (أسعار من الإدارة، snapshot عند الشراء)، الاستحقاق من الخادم (`aiPlanFor`)، حالات الاشتراك، المحاكاة `TEST_NO_TRANSFER` بلا تجديد تلقائي، فصل حقوق السوق عن حصص AI.

**المُنفّذ:** `lib/subscription-billing.ts` + `routes/integrations.ts` + جدول `billing_webhook_events`.

- آلة حالات واحدة لكل حدث فوترة (تفعيل، تجديد، فشل دفع → `PAST_DUE` بلا استحقاق، إلغاء عند نهاية الفترة، انتهاء، استرداد → إيقاف فوري محافظ).
- `GET /business/plan-change-preview`: ترقية بعد تأكيد الدفع، تخفيض عند نهاية الفترة، `proration: NOT_APPROVED`، لا مبالغ مخترعة.
- `POST /business/subscription-checkout`: دون مزود مسجل → **503 `BILLING_PROVIDER_NOT_CONNECTED`، لا صف ولا خصم**. مع مزود: اشتراك `PENDING` لا يمنح شيئًا حتى webhook موقّع.
- `POST /billing/webhooks/:providerKey`: مزود غير مسجل → 503 دون تخزين؛ توقيع خاطئ → 401 ويُسجل `REJECTED`؛ تكرار → من السجل؛ مبلغ/عملة لا تطابق اللقطة → `AMOUNT_MISMATCH`؛ فترة أقدم → `INVALID_PERIOD`.
- إعادة الضبط: الحصص تتجدد بالفترة التقويمية في `aiUsage.period`؛ الخطة تُقرأ من الاشتراك الحي.

**متبقٍ / قرارات:** الأسعار والعملة والضريبة، الحصص المعتمدة، التجديد التلقائي، الاسترداد، مواءمة فترة الحصة مع فترة الفوترة، مزود الفوترة وMoR.

**المُعاد استخدامه:** `model-gateway.ts` و`interpretWithModel` (runtime واحد، لا تكرار)، تسجيل المزود حسب البيئة والسوق.

**المُنفّذ:** مزود محايد `OPENAI_COMPATIBLE` (`DINAR_AI_BASE_URL` + `DINAR_AI_MODEL` + `DINAR_AI_API_KEY`)؛ نموذج احتياطي اختياري `DINAR_AI_FALLBACK_*` يُجرّب مرة بعد فشل الأساسي (ليس للمهلة)؛ `DINAR_AI_MAX_RETRIES` (0–2)؛ `DINAR_MODEL_TIMEOUT_MS`؛ رموز مخزّنة ومعرف الطلب من المزود؛ اعتمادات تُرسل لـ HTTPS فقط (HTTP للـ loopback في التطوير)؛ `describeAIModelReadiness` بلا أسرار؛ `GET /admin/integrations/readiness`.

**متبقٍ / قرارات:** اختيار المزود/النموذج، اتفاقية المعالجة ونقل البيانات، تسجيل staging/production (غير موجود عمدًا)، اختبار حي بميزانية.
