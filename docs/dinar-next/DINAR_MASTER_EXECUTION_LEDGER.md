## الحالة المختصرة

- النتائج الهندسية في `PRE_INTEGRATION_FINAL_ACCEPTANCE.md` تغطي اختبارات قاعدة مؤقتة ومتصفحًا لتلك الجولة، ولا تعني أن بوابات المالك أو التكاملات الحية أُغلقت.

- حالة Railway في `searchIntegrations` ما زالت `connect` مع الملاحظة `not mounted yet; retried each turn`. أُرفق التكامل مرة سابقًا، لكن الحالة لم تتغير؛ لا توجد skill file أو callbacks، فلا يمكن إجراء استعلام Railway API. **هذا لم يمنع فحص قاعدة Preview للقراءة فقط** عبر `preview-migration-check.mjs` وTLS المثبت؛ لكنه لا يغيّر حالة MCP ولا يثبت بيانات backup/PITR. وثائق Replit توصي من Project Editor بفتح **Integrations/Connectors** ثم Railway واختيار **Reconnect/Manage**؛ ولـMCP غير المركّب، التحقق من URL والمصادقة في MCP settings أو إعادة التفويض من لوحة MCP إذا كانت الحالة disconnected. لا يثبت HTTP 400 أن النسخ معطلة، ولا يحدد إن كان خلل صلاحيات أو endpoint.
- لا وصول إلى إنتاج، ولا تغيير أسرار، ولا إنشاء/استعادة خدمة أو قاعدة، ولا تشغيل هجرة مُدارة.
- تدقيق `717400a` أعاد فحص Preview عبر TLS موثّق ومعاملة `READ ONLY`: 28/40 migration، آخرها `0027_personal_intelligence`، وhashes لأول 28 تطابق الدفتر؛ `0028`–`0039` معلّقة. لا جلسات أخرى، وكل حواجز البيانات الخاصة بالسلسلة كانت صفراً. لا يعني `verdict=PASS` من preflight أن Preview جاهزة؛ `/api/readyz` تظل محجوبة حتى تطبيق الترحيلات بعد موافقة منفصلة.
- الحكم النهائي للتدقيق: **CODE_COMPLETE_BUT_RUNTIME_BLOCKED**. مراجعة المصدر والبناء نجحا، لكن لا قبول تجاريّاً حياً ولا رحلة متصفح مصادَق عليها في هذه الجولة. التفاصيل ومصفوفة التصنيف في `DINAR_FINAL_PRICING_NEGOTIATION_ACCEPTANCE.md`.

### INFRA-01 — إثبات النسخ الاحتياطية وPITR

- **المالك:** مالك DINAR / مسؤول Railway.
- **الشدة:** حرجة — الاستعادة والبيانات الدائمة.
- **إعادة الإنتاج / الحالة:** `searchIntegrations` يعيد `connect` و`not mounted yet`; بعد إرفاق سابق بقيت الحالة كما هي، ولم تظهر skill file أو callbacks. لذلك لا يمكن تحديد السبب الداخلي لرد HTTP 400 السابق ولا حالة backups أو PITR. لا يوجد دليل على أن النسخ معطلة.
- **الدليل:** التقرير المذكور يحدد مشروع `dinar-development-canonical`، بيئة `development`، خدمة `Postgres`، لكنه يحذر من أن غياب بيانات النسخ في واجهة القراءة لا يثبت عدم وجود نسخ.
- **التصحيح المطلوب:** أولًا، في Replit Project Editor افتح لوحة **Integrations** أو **Connectors** من الشريط الجانبي، اختر Railway ثم **Reconnect** أو **Manage**. إذا بقي MCP غير مركب، افتح إعدادات MCP وتحقق من عنوان الخادم والمصادقة؛ لا ترسل credentials في الدردشة. أعد التفويض فقط إذا أظهرت اللوحة أنه disconnected. توقف عن هذا الفرع حتى تصبح الحالة `ready`، ولا تدّع أن الاتصال يعمل الآن. بعد ذلك، في Railway Dashboard اختر المشروع `dinar-development-canonical`، بيئة `development`، خدمة `Postgres` المحددة في `RAILWAY_BACKUP_READINESS.md`، ثم **Backups**. أرسل: حالة PITR، صحة WAL archiver، أقدم/أحدث وقت استعادة، آخر volume backup ناجحة مع الوقت والحالة، وجدول النسخ التلقائي. لا تفعّل PITR ولا تنشئ backup أو خدمة.
- **إعادة الاختبار المستقلة:** بعد عودة MCP إلى `ready` أو تقديم لقطة موثوقة من Dashboard، طابق البيانات. لا تدّعِ قابلية الاستعادة قبل استعادة معتمدة إلى خدمة شقيقة.
- **الحالة:** **محجوب بعمل المالك وإتاحة Railway MCP**؛ حالة النسخ الفعلية **غير معروفة**.
- **متابعة المشروع:** المهمة المقترحة لإثبات مسار الاستعادة ما زالت **PENDING / BLOCKED BY CONCURRENCY_LIMIT**؛ لم تُسند أو تُنفذ.

### DB-01 — استعادة معزولة ثم بروفة الترحيلات

- **المالك:** مالك DINAR للموافقة؛ DBA/الهندسة للتنفيذ.
- **الشدة:** حرجة قبل تغيير أي قاعدة مُدارة.
- **إعادة الإنتاج / الحالة:** journal الحالي **39 إدخالًا** من `0000` إلى `0038`، ويشمل 0037 و0038. اختبار clone guard قرأ ملفات SQL الفعلية وطابق الـhashes للـ39 إدخالًا مع القائمة المثبتة؛ رفض journal بطول 38 أو 40، وتعديل 0037 وإعادة تسمية migration. لم يُشغّل runner على clone ولم تُنشأ شقيقة. عدد migrations المطبق على Railway canonical يحتاج تأكيدًا حديثًا على نسخة معزولة.
- **الدليل:** `CLONE_TLS_SAFE_REHEARSAL.md`، `RAILWAY_MANAGEMENT_READINESS.md`، و`lib/db/src/clone-migration-guard.ts`.
- **التصحيح المطلوب:** بعد إغلاق `INFRA-01` وموافقة منفصلة على استعادة نسخة كاملة، تحقق من هوية الشقيقة وTLS/CA المستقلين وإعداداتها. شغّل `migrate:clone` فقط عليها بعد مراجعة الدفتر وخط الأساس؛ لا توجهه إلى Railway canonical أو الإنتاج.
- **إعادة الاختبار المستقلة:** أُعيد تشغيل `development-tls.test` على database loopback مؤقت: **7 pass / 0 fail / 1 skipped** (اختبار TLS الحي متخطى عمدًا). هذا يثبت حواجز الهدف والهوية وTLS، baseline ذي 28 إدخالًا، وjournal الحالي ذي 39 إدخالًا؛ لا يثبت اتصالًا أو migration حيًا. بعد إثبات النسخة وموافقة المالك فقط: افحص هوية الشقيقة وhashes الدفتر والجداول/القيود وinvariants ثم smoke test محدود عليها.
- **الحالة:** **متحقق محليًا جزئيًا؛ التنفيذ الحي محجوب بموافقة المالك وإثبات الاستعادة**.
