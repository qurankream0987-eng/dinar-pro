# Source-aware research design v1 — design only, external retrieval disabled

Owner clarification: evaluate OpenRouter native `openrouter:web_search` and `openrouter:web_fetch` first; compare Gemini Google Search grounding only when supported by the selected OpenRouter model/provider route; evaluate Brave Search or Exa only for measurable benefit. No multiple search providers by default. A read-only OpenRouter documentation request failed with proxy CONNECT 403 (curl 56, HTTP 000), so current API names, schemas, availability and prices are not independently verified. The tool names here are owner-specified evaluation targets, not a claim that the current gateway implements them.

## Existing capabilities reused

- tool-registry searchListings / getResource: current internal market reads, server-owned resultSetId and exact resources. C-12 binding and Card Envelope remain unchanged.
- searchDomains: existing scoped DINAR domain discovery, not internet search.
- searchPartnerOffers: approved partner/site/integration offers, external referral cards, sourceCheckedAt and stale handling, not arbitrary web search. Existing connect/partners.ts verifies merchant/site/integration status and rechecks destination authority at click time.
- connect/website-catalog.ts inspects bounded HTML/JSON-LD through existing ConnectNetwork and records pageDigest/observedAt. It is an approved merchant ingestion path, not a general browser/search engine. Reuse/review its SSRF, destination and bounded-fetch controls rather than creating a second unrestricted fetcher.
- No existing general external-web research tool or approved knowledge corpus was established. Current prompt truthfully states no live internet. This package leaves that statement and all retrieval activation unchanged.

## Proposed source contract

A server-owned retrieval bundle would carry version, actor/conversation/market/current-turn binding, query digest (not raw private profile), provider identity, retrieval status, budget receipt and a bounded sources array. Source entries carry server-assigned citation ID, sourceKind, actual source URL (when applicable), title, retrievedAt, publishedAt only when explicitly supplied by source, content hash, bounded quoted excerpt, freshness/verification labels and provenance. Model output may refer only to IDs issued for the current bundle; unknown/missing/mismatched citations are rejected. Do not invent URLs, publication timestamps or trust labels.

| Source kind | Authority | Citation/resource requirements |
|---|---|---|
| INTERNAL_MARKETPLACE | Server owns current commercial facts and action lifecycle; seller prose remains unverified | Reuse existing resultSetId, resource identity, actor/market binding and current successful-read evidence. Canonical resource identity need not have a public URL. |
| EXTERNAL_WEB | Untrusted evidence for general research only; no transaction authority | Exact fetched/source URL plus retrieval timestamp, provider and content digest; label external and stale/failed reads. No listing/cart/order IDs derived from page text. |
| APPROVED_KNOWLEDGE | Approved corpus/version with access and effective dates; not automatic permission for money/actions | Approval ID/version, source-document identity, real URL if available, validity/scope and quote/page locator. No fabricated public URL for private documents. No corpus is approved by this design. |

Existing partner commerce stays in its approved EXTERNAL_REFERRAL lifecycle; do not relabel a partner offer as an internal purchasable listing or a generic web result. Do not extend Card Envelope or add a renderer/store for this design. Browser citation display would require Claude/Replit agreement on a minimal backward-compatible contract before implementation.

## Recommended provider strategy and evaluation order

1. **Primary candidate: native OpenRouter web_search/web_fetch.** Verify official availability and exact tool/request/result/citation schemas, provider/model compatibility, separately billed search/fetch charges, privacy controls, bounded tool invocation and source-URL provenance. Existing gateway currently sends neither native research tools nor plugins. Do not confuse a tools-capable model with a working native web service. Prefer this single provider path if it can meet DINAR's authorization, accounting and evidence contract.
2. **Comparison candidate: Gemini Google Search grounding through OpenRouter.** Only evaluate a selected route that explicitly supports grounding; do not assume direct Gemini API support implies OpenRouter route support, or that ordinary function tools and grounding can be combined. Validate native grounding metadata/citations, billing units, privacy restrictions and recoverability. No grounding flag is invented or enabled here.
3. **Contingent candidate: Brave Search or Exa.** No default integration. Evaluate only after a sealed comparison demonstrates improved Arabic coverage/citation correctness, reliability, latency or cost under the same workload. If native routing cannot provide enforceable budgets/source provenance, document that gap before considering a scoped server-side adapter. Do not repurpose an approved merchant connector for arbitrary domains.

Use the same eight owner scenarios and candidate routes, repeated under a separately approved cap, to measure citation support/accuracy, source coverage, Arabic relevance, freshness, p50/p95 latency, failure/recovery rate and fully billed cost (inference plus search/fetch). Freeze a scorecard and owner acceptance thresholds before spending; no empirical winner or actual prices are claimed now. Recommend native OpenRouter as the first evaluation candidate, not as a verified production-ready service. No additional search provider, framework or standalone engine was installed.

**Implemented offline boundary:** src/ai/research-source-contract.ts plans requested source kinds without dispatch, validates bounded source bundles/current actor-conversation-market-turn binding, requires an explicit server-bound bundle reference for older turns, verifies internal result IDs against supplied authorized result sets and knowledge approval versions against supplied approvals, and rejects unknown citation IDs/failed-result citations. The eight owner scenarios plus five negative/approval controls are frozen in research-source-contract.test.ts. General/no-search and marketplace-only are separate from explicit web/mixed requests. These helpers are not registered as active model tools and no raw HTTP request can create a trusted bundle through this package. A future adapter must supply independently authorized identities; passing a schema alone is not authorization.

External sources cannot carry resourceId/allowedActions fields; known instruction-like excerpts are quarantined and cannot be cited. This heuristic is defense in depth, not a proof against all prompt injection. All excerpts remain untrusted and cannot invoke commercial operations. URL syntax checks reject credentials, IP literals and suspicious secret query fields; DNS/redirect/SSRF checks remain a required future fetcher responsibility. Query preflight rejects detected phone/email/credential material but is not a complete PII classifier; approved query minimization is still required. No live prompt-injection defense or provider privacy outcome is certified.

## Budgets, privacy and hostile documents

Before activation, owner approves per-turn/account/global search counts and money ceiling, timeouts, domains/provider, retention and legal basis. Reserve search spend before dispatch, including separately billed plugins; bound retries and concurrent reservations, settle actual usage or keep a conservative hold for unknown billing. Existing text-inference reservation does not by itself cover search-vendor fees. No new policy/quota is invented here.

Suggested engineering bounds to review, not active configuration: at most 2 searches/turn, 5 quoted sources, 3-second search deadline within existing turn deadline, 128 KiB document ceiling, 6,000 total excerpt characters. Decide and version these before implementation. Empty/failed search must not appear as successful grounded research.

Default deny private user history, telephone numbers, credentials, confidential uploads and private business fields in search queries. Use an explicit minimal query; require separate approval for sensitive document processing. Reject private/loopback/link-local targets, credential-bearing URLs and unauthorized redirects; revalidate DNS/address at every fetch and never forward DINAR cookies/provider keys to documents. Do not execute page JavaScript or fetch embedded instructions/resources automatically.

Retrieved text is untrusted quoted DATA, never system/developer messages or tool definitions. Reject instruction-like requests to disclose secrets, change permissions, alter system behavior, make transactions or invoke tools from documents; do not rely solely on a regex classifier or a prompt warning. Enforce fixed server tool schemas, authorized reads, no write authority and no retrieved-text-controlled tool execution. Detect suspicious content for diagnostics without logging private content. A model answering a malicious quotation cannot confer purchase/payment authority. Claim/citation checks and adversarial fixtures are required before activation; no claim of solved prompt injection is made from this unexecuted design.

Acceptance must include malicious snippets, fake citations, stale dates, failed/empty searches, cross-market/account references, two-tab recovery, privacy redaction, SSRF/redirect rebinding, concurrent spend denial and web claims about stock/payment. Tests must assert exact source identities and zero unauthorized mutations. External web results must never replace authoritative internal prices, inventory, confirmation or receipts.
