# Context, memory and reproducible evaluation

Implemented in the existing engine:

- Long prior turns retain the first 500 characters and the bounded tail, with an explicit omitted-content marker. Existing 1200-character entry/9000-character history/10-turn limits remain; this preserves late user corrections and code errors without increasing prompt budget.
- Memory quotes label USER_QUOTE versus ASSISTANT_UNVERIFIED/UNVERIFIED_QUOTE. Direct matches precede historical derived summaries, with fair per-section excerpts in the same 1200-character block. No historical assertion becomes a server fact or authorization.
- Existing prompts now explicitly cover Gulf, Levantine, Egyptian and Maghrebi understanding, current corrections/topic shifts, concise checkable reasoning and honest code/source verification. These are instructions, not evidence of GPT-class fluency or reasoning quality.

PostgreSQL memory remains owner-scoped with existing business/privacy filtering, bounded lexical/trigram search, 400ms database statement timeout and extractive summaries with source IDs/watermarks. No vector database, embeddings, model training, new memory store or private-data export was introduced. Short per-section excerpts can lose detail; the model must ask for missing context rather than invent it. Source records and existing scoped reads remain the recovery path.
