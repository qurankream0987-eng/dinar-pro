## حدود السلامة

- قاعدة الاختبار كانت PostgreSQL loopback على `127.0.0.1:55479` داخل مجلد مؤقت أنشئ لهذا التشغيل.
- أُنشئت قاعدة قالب مهاجرة محلياً، مع وحدات fixtures للأسواق والأسعار فقط. لم يُستخدم seed شامل.
- لم يُوصل أي اختبار بقاعدة Railway أو Replit المدارة. اختبارات acceptance أنشأت بياناتها داخل قواعد محلية منفصلة فقط؛ حُذفت تلك القواعد وأُوقفت PostgreSQL بعد اكتمال الاختبارات.
- الاستعلام على Railway development كان للقراءة فقط. لم تُطبق الهجرات `0028–0036`.
- لم يحدث نشر أو دفع إلى GitHub أو اختبار إنتاج أو تغيير عمولة أو إنشاء حركة أموال حقيقية. بوابات نماذج القبول كانت scripted ولم تتصل بمزوّد خارجي.
- ملف التعليمات المرفق بقي دون تعديل.

## الإصلاحات المقبولة محلياً

1. إزالة إدخال البيئة الفارغ ذي الاسم الشبيه بـ GitHub credential من `.replit` باستخدام مسار التحقق المخصص؛ لم تُقرأ القيمة ولم تُطبع أو تُستخدم.
2. إضافة تصريح `BDINAR_PHASE1_ACCEPTANCE=development` إلى سكربت phase1؛ كان السكربت يفتقد التصريح المطلوب من حارس الاختبار.
3. تحديث Orval إلى `8.43.0` وVite إلى `7.3.7` لمعالجة نتيجتي dependency audit، وإعادة توليد ملفات API/Zod.
4. تثبيت نسخة React Query المولدة على v5، المطابقة للنسخة المستخدمة في مساحة العمل.
5. اجتاز `pnpm --filter @workspace/api-spec run codegen` و`pnpm run build` بعد التغييرات. أعيد تشغيل خدمتي API والويب؛ بدأت كلتاهما دون أخطاء بدء تشغيل.
