# DINAR — مصفوفة قبول البيع الحواري وجاهزية المعاملة

**النطاق:** أمثلة البيع الأربعون في `DINAR-CONVERSATION-FIRST-SELLING-DIVERSE-ACCEPTANCE-EXAMPLES`، مع قواعد جمع التواصل والموقع والدفع في `DINAR-SELLER-CONTACT-LOCATION-PAYMENT-CONVERSATIONAL-COLLECTION-RULES`.

**هذه مصفوفة تحليل للحالة الحالية وخطة اختبار، وليست تصريحًا بأن كل السيناريوهات نُفذت أو اختُبرت.** الأمثلة اختبارات للعمومية وليست قائمة مغلقة أو مبررًا لإنشاء معالجات متخصصة.

**تصحيح معرّفات القبول:** C01–C27 تخص اختبارات Block C لسجل العمل/الخصوصية المهنية، وليست اختبارات خصوصية التواصل. تُشار أدلة التواصل بمعرّفات `CONTACT-*` حيث وُجدت، أو باسم الاختبار الوصفي `authenticated contact browser microclosure` في `contact-browser-microclosure.test.ts`. لا تُنسب C01–C16 إلى التواصل.

## القرار المعماري والحدود

المسار المطلوب لكل السيناريوهات:

`محادثة → مسودة بيع canonical واحدة → خدمات السوق الحالية → أسطح مضمّنة اختيارية → المحادثة نفسها`

- لا معالج بيع إلزامي بحسب الفئة. يُسمح بمساعد يدوي صغير اختياري، ويجب أن يعدّل المسودة نفسها.
- الموقع العام (مدينة/منطقة) منفصل عن عنوان التسليم الدقيق، ورقم الدخول لا يصبح رقم تواصل سوقيًا تلقائيًا.
- لا نشر دون مراجعة وموافقة صريحة. اقتراحات الصور تظل مؤقتة حتى يعتمدها البائع.
- **حد الدفع الحالي:** الدفع الفعلي مؤجل؛ الوضع هو `TEST_NO_TRANSFER` / `SIMULATION_ONLY`، ولا يُفعّل مزود دفع أو تحويل أموال. يدعم سجل السوق حاليًا نقدًا مباشرًا حسب إعداد السوق، لا تفضيل دفع لكل إعلان. لذلك لا تُعامل إضافة CARD/Visa لكل بائع كمتطلب قابل للتفعيل الآن؛ يلزم قرار تجاري/قانوني ومزود مرخّص قبل تغيير هذا الحد.

## معنى الحالة

- **مغطى:** يوجد اختبار آلي مباشر للسلوك المحدد، وليس بالضرورة لكل تفاصيل المثال.
- **جزئي:** توجد بنية أو تغطية لسلوك مجاور، لكن الاختبار الشامل المطلوب غير موجود.
- **فجوة:** النموذج أو مسار التنفيذ الحالي لا يملك الوظيفة المطلوبة.
- **غير متحقق:** لم أجد دليل اختبار مباشر كافيًا؛ لا أستنتج النجاح من وجود كود قريب.
- **مؤجل:** يتعارض التفعيل الآن مع حد الدفع/الاعتماد الحالي.

| CONTACT-03 | رقم التحقق/الدخول لا يُنشر تلقائيًا | **مغطى جزئيًا** — الاختبار المركز يفحص غياب الرقم من المسودة/المراجعة، وعدم النشر قبل التأكيد، وحاجز الهاتف غير المتحقق؛ لم يُفحص تسجيل السجلات أو رحلة المتصفح. |
| LOCATION-01 | المدينة/الحي يُستخرجان من نص طبيعي | **جزئي** — حقلا `city` و`area` وتحليل أولي موجودة؛ اختبر صياغات عربية متعددة مع عدم سؤال البائع ثانية. |
| LOCATION-02 | الموقع العام لا يكشف GPS أو عنوانًا دقيقًا | **مغطى** — فحوص الموقع العام ترفض العناوين الخاصة/الدقيقة؛ ثبّت اختبار واجهة/نشر يحظر تسريب الإحداثيات. |
| LOCATION-03 | عنوان التسليم الدقيق يبقى ضمن الطلب/التوصيل ولا يبدل موقع الإعلان | **جزئي** — توجد حدود وسياقات مستقلة للموقع؛ أضف اختبارًا بعد الشراء يثبت بقاء منطقة الإعلان كما هي وعدم إظهار العنوان علنًا. |
| PAYMENT-01 | البائع يحدد قبول النقد على مستوى الإعلان | **فجوة** — `CASH_DIRECT` قدرة سوقية، لا تفضيلًا محفوظًا لكل مسودة/إعلان؛ لا تنشئ محركًا ماليًا موازيًا. |

| PAYMENT-03 | تسجيل قبول النقد والبطاقة معًا | **مؤجل** — يعتمد على دعم البطاقة؛ حاليًا يجب ألا يوحي النظام بأن الطريقتين متاحتان. |
