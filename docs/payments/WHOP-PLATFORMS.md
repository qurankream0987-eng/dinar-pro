# متغيرات البيئة — Whop for Platforms

DINAR يشغّل مدفوعات البطاقة عبر **Whop for Platforms**. كل القيم تُقرأ على الخادم فقط، ولا
يصل مفتاح API إلى المتصفح. البيئة الافتراضية **sandbox**، ولا يتحول الخادم إلى الإنتاج
إلا عند ضبط `WHOP_ENVIRONMENT=production` صراحةً مع مفاتيح إنتاج خاصة به.

| المتغير | إلزامي | الافتراضي | المعنى |
| --- | --- | --- | --- |
| `WHOP_ENABLED` | نعم للتفعيل | `false` | `true` يفعّل مسارات Whop؛ أي قيمة أخرى تُبقيها معطّلة. |
| `WHOP_ENVIRONMENT` | لا | `sandbox` | `sandbox` أو `production` حرفيًا. أي قيمة أخرى (بما فيها `prod`) تُحسم إلى sandbox. |
| `WHOP_API_KEY` | نعم عند التفعيل | — | مفتاح الخادم للبيئة المختارة. لا يُستخدم مفتاح sandbox في الإنتاج ولا العكس. |
| `WHOP_WEBHOOK_SECRET` | نعم عند التفعيل | — | سر توقيع webhook الطلبات (`/api/whop/webhooks`, `ws_…`) لنفس البيئة. |
| `WHOP_BILLING_WEBHOOK_SECRET` | نعم لاشتراكات جاسم | — | سر webhook الاشتراكات المستقل (`/api/billing/whop/webhook`). لا يُستعمل سر الطلبات مكانه. |
| `WHOP_COMPANY_ID` | نعم عند التفعيل | — | معرّف حساب المنصة (`biz_…`) الذي يملك fee markup الافتراضي. |
| `WHOP_USD_PER_JOD` | نعم عند التفعيل | `0` | سعر تحويل ثابت JOD→USD. يجب أن يكون موجبًا. |
| `WHOP_FEE_PERCENT` | لا | `5` | نسبة عمولة جاسم الثابتة على قيمة البيع لكل الفئات (قرار المالك 2026-11-25). |
| `WHOP_BLOCKED_COUNTRIES` | لا | — | دول إضافية محظورة (`IQ,RU,…`). القائمة الافتراضية `IQ,IR,KP,SY,CU` لا يمكن إزالتها. |

ملاحظة: `configured` يصبح `true` فقط عندما `WHOP_ENABLED=true` وكل الإعدادات صحيحة.
عندها فقط تظهر واجهات الدفع. أي خلل يُعرض للإدارة كأسماء إعدادات ناقصة، وليس كقيم.

## روابط البيئتين (لا تُخلط)

| | Sandbox | Production |
| --- | --- | --- |
| API | `https://sandbox-api.whop.com/api/v1` | `https://api.whop.com/api/v1` |
| Dashboard | `https://sandbox.whop.com/dashboard/developer` | `https://whop.com/dashboard/developer` |
| SDK | `WhopEnvironment.Sandbox` (`environment: "sandbox"`) | `WhopEnvironment.Production` (الافتراضي) |

## اختبار Sandbox (بطاقات الاختبار)

من دليل Whop: أي تاريخ مستقبلي وأي CVC وأي عنوان.

| البطاقة | النتيجة |
| --- | --- |
| `4242 4242 4242 4242` | نجاح |
| `4000 0000 0000 0002` | رفض |
| `4000 0000 0000 0341` | رفض عند الحفظ لاحقًا |
| `5385 3083 6013 5181` | 3DS، كلمة المرور `Checkout1!` |

قيود sandbox: **لا payouts ولا crypto ولا Apple/Google Pay**. لذلك يمكن اختبار الدفع
والـ webhooks والاسترداد، لكن **لا يمكن** إكمال اختبار السحب (payouts portal) في sandbox.

## قائمة الانتقال من Sandbox إلى Production

1. أنشئ مفاتيح **إنتاج** في `https://whop.com/dashboard/developer`، ولا تعِد استخدام مفاتيح sandbox.
2. أنشئ webhook إنتاجًا يشير إلى `https://<النطاق>/api/whop/webhooks` واحفظ سرّه في `WHOP_WEBHOOK_SECRET`.
3. اضبط `WHOP_COMPANY_ID` لحساب المنصة الإنتاجي، وأضف `payment_markup` بالنسب المعتمدة.
4. اضبط `WHOP_USD_PER_JOD` بسعر التحويل المعتمد قانونيًا، وثبّته في الوثائق المالية.
5. أبقِ `WHOP_FEE_PERCENT=5` (النسبة الثابتة المعتمدة)؛ لا شرائح.
6. أبقِ `WHOP_BLOCKED_COUNTRIES` (الافتراضية لا تُحذف) وأضف ما يلزم تشغيليًا.
7. اضبط `APP_ORIGIN` إلى نطاق الإنتاج (تُبنى منه روابط العودة والتحديث).
8. بدّل `WHOP_ENVIRONMENT=production` مع مفاتيح الإنتاج **في نفس النشر**؛ لا تخلط بيئتين.
9. نفّذ عملية شراء حقيقية صغيرة، وتحقق من: `payment.succeeded`، تحديث الطلب، رسالة النظام،
   وسجل `whop_events`، ثم استرداد كامل عبر لوحة الإدارة.
10. راقب `GET /api/whop/status` (إدارة) للتأكد من `configured=true` و`environment=production`.

## ما يتغير عند التبديل

- لا يتغير الكود ولا قاعدة البيانات؛ تُقرأ البيئة مرة واحدة عند بدء العملية.
- سجلات `whop_checkouts.data.environment` تحفظ البيئة التي أنشأت كل دفع، فلا تُخلط البيئتان في التقارير.
- الدفعات القديمة من sandbox لا تُسترد في الإنتاج؛ كل بيئة مستقلة.

## حدود معروفة (يجب قراءتها قبل الإطلاق)

- **عمولة لكل حساب، لا لكل طلب.** Whop يطبّق `payment_markup` على مستوى الحساب، وواجهة
  الدفع المستضافة لا تقبل `application_fee_amount` لكل طلب. لذلك يتحقق الخادم أن markup
  البائع (أو markup المنصة الافتراضي) يساوي نسبة العمولة المحفوظة في الطلب، ويرفض إنشاء
  الدفع عند أي اختلاف (`WHOP_COMMISSION_NOT_CONFIGURED` أو `WHOP_COMMISSION_TIER_UNAVAILABLE`).
  مع النسبة الثابتة المعتمدة (5% لكل الطلبات) يكفي markup واحد بقيمة 5% لكل بائع، فلا حاجة لشرائح.
  الطلبات القديمة المحفوظة بنسبة 10% تُرفض في هذا المسار بدل تغيير عمولتها المحفوظة.
- **الاسترداد يحتاج تأكيد webhook.** `payments.refund` يُعيد الدفعة المحدّثة، والنجاح النهائي
  يصل عبر `refund.updated`. لذلك تبقى الحالة `REQUESTED` حتى يصل الحدث الموقّع.
- **لا Elements في المتصفح.** استُخدم رابط الدفع المستضاف بدل تضمين عناصر Whop، لأن ذلك
  يتطلب حزمة متصفح إضافية لم تُعتمد. `BalanceElement` و`WithdrawButtonElement`
  و`WithdrawalsElement` غير مستخدمة؛ البديل المعتمد هو `accountLinks` مع
  `use_case: "payouts_portal"`.
- **الدول المحظورة** تشمل العراق وإيران وكوريا الشمالية وسوريا وكوبا، وتُطبَّق عند التسجيل
  وعند إنشاء الدفع على دولة المشتري والطلب والبائع. هذا حجب تشغيلي، وليس حكمًا قانونيًا.

## سجل ترخيص `@whop/sdk@2.7.0`

- الحزمة الرسمية من `https://github.com/whopio/whopsdk-typescript`.
- فحص الترخيص: `package.json` داخل الحزمة **بلا حقل `license`**، وملف `README` داخل الحزمة
  لا يذكر ترخيصًا، وسجل npm لـ `2.7.0` يقول `License: not recorded`، وواجهة GitHub API
  تُعيد `license: null` ولا يوجد ملف `LICENSE` في المستودع (استجابة `404`).
- الاستنتاج: **لا يوجد ترخيص مصرّح به**؛ الحقوق محفوظة افتراضيًا. الاعتماد أُضيف بموافقة
  المالك الصريحة كحزمة المزوّد الرسمية، لكن هذا **خطر قانوني غير محسوم** ويجب الحصول على
  إذن كتابي من Whop أو اعتماد مسار HTTP بديل قبل الإطلاق التجاري. لا تتخذ هذه الوثيقة
  حكمًا قانونيًا.


## قرار المالك (2026-11-25)

- العمولة **5% ثابتة من قيمة البيع لكل الفئات**، بلا شرائح.
- **لا ضمان (Escrow)**: جاسم لا يستلم أموال البائعين ولا يحتفظ بها؛ الدفع يُنشأ على حساب البائع (Direct Charge) والعمولة رسم تطبيق.
