# تقرير الجاهزية النهائي — تجهيز DINAR على Railway

**تاريخ الفحص:** 3 نوفمبر 2026

**الحالة العامة:** `PREPARED_NOT_DEPLOYED`
**النتيجة:** أُعدّت حزمة البنية التحتية واختُبرت محليًا. لم يتم نشر DINAR أو تغيير أي مورد على Railway.

## الحالة الفعلية على Railway

- المشروع الظاهر هو `dinar-development-canonical`، وفيه بيئة `development` فقط.
- يوجد PostgreSQL واحد مع نسخة واحدة وقرص بحجم 500 MB في المنطقة `iad`.
- لم يظهر خادم تطبيق DINAR أو مخزن كائنات أو نطاق مخصص أو بيئة staging منفصلة.
- يوجد منفذ TCP عام لقاعدة البيانات؛ حُذف عنوانه من التوثيق. لم يُستخدم للتطبيق أو للاختبارات.
- حالة تغييرات Railway متضاربة: واجهة الحالة تشير إلى `EnvironmentPatch` معلّق، بينما أوصاف البيئة والخدمة لا تعرض تغييرات. لم يُقبل التغيير أو يُرفض أو يُطبّق.
- سجل الترحيلات الحالي في قاعدة Railway غير متحقق منه. تقرير قراءة سابق بتاريخ 3 نوفمبر سجّل 28 من 51 ترحيلًا؛ لذلك لا تُستخدم قاعدة التطوير كهدف للتطبيق أو الترحيل.
- حالة النسخ الاحتياطي وPITR والأرشيف والاحتفاظ والاستعادة `UNVERIFIED`. لم يُفعّل PITR ولم تُنشأ موارد مدفوعة.

## ما أُعدّ

أُضيفت الوثائق الأربعة عشر المطلوبة ضمن `docs/deployment/railway/`. تتضمن جرد الحالة، تصميم البيئات، إعداد Docker، إجراءات قاعدة البيانات والترحيل، النسخ الاحتياطي والاستعادة، تخزين الملفات، مصفوفة أسماء المتغيرات، مراجعة الأمن، التنبيهات والتكلفة، وإجرائي staging والإنتاج مع بوابات موافقة واضحة.

أُصلح عيبان محدودان في إعداد التشغيل: يعمل Docker من مجلد خادم API حتى يجد فحص الجاهزية سجل الترحيلات الصحيح، ويعالج مجمع PostgreSQL أخطاء الاتصالات الخاملة دون إسقاط عملية API. لم يتغير منطق الأعمال.

## نتائج الاختبار المحلي

- بناء Docker مع تثبيت الاعتماديات المقفول: ناجح.
- قاعدة PostgreSQL 18.6 محلية مؤقتة: طُبّقت 51/51 ترحيلًا.
- اختبارات الجاهزية: 15/15 ناجحة.
- اختبارات الأصل الواحد والواجهة/API: 8/8 ناجحة.
- اختبارات S3 على خادم محاكاة محلي: 7/7 ناجحة؛ لا يثبت ذلك توفر مخزن حي.
- في تشغيل الإنتاج المحلي: `/api/healthz` و`/api/readyz` والصفحة الرئيسية أعادت 200؛ حمّل Chromium صفحة DINAR.
- عند إيقاف PostgreSQL المحلي بقيت API تعمل؛ بقيت الجاهزية 503 ثم عادت 200 بعد استعادة قاعدة الاختبار.
- إيقاف API بإشارة SIGTERM أعاد الرمز 0، وأعاد تشغيلها أعاد الجاهزية 200.
- بدء API على قاعدة فارغة أعاد 503 ولم ينشئ جدول سجل الترحيلات تلقائيًا.
- اختبار القبول الأمني الكامل على قاعدة PostgreSQL 18.6 محلية مؤقتة: 12/12 ناجحة، 0 فشل، 0 تخطٍ. كانت المحاولة الأولية على قاعدة فارغة 3/12 ناجحة و9/12 فاشلة بسبب غياب أسواق KW وJO وSA النشطة وإصدارات أسعارها؛ تعذر بعدها تجهيز العروض والطلبات التي تعتمد عليها اختبارات الملكية والصور والطلبات والإدارة. أُعيد التشغيل باستخدام وحدة تجهيز الأسواق المعتمدة في قاعدة loopback جديدة. لم تُعدّل قواعد الصلاحيات أو الثوابت المالية أو تأكيدات الأمن.
- SHA التطبيق الذي اجتاز الاختبار: `5a8cfd7693b0b717102c1fdef309e0b19f3df733`. تتضمن وثيقة الإثبات 15 تفاصيل المتطلبات الدقيقة، أسماء الاختبارات التسعة التابعة للبيانات الناقصة، نتائج pass/fail/skip، وخريطة تغييرات المصدر الخمسة لمراجعة Claude.
- لم تتصل الاختبارات بقاعدة Railway أو مخزن حي أو مزود AI/SMS/دفع.

## مخاطر ومتطلبات متبقية

1. التحقق من حالة PITR والنسخ الاحتياطي وإجراء استعادة إلى خدمة منفصلة بموافقة المالك.
2. حسم تعارض ترحيل `0051`: يحتوي فرع Wave02 على `0051_order_multi_item_money.sql`، ويحتوي فرع D16 على `0051_d16_legal_readiness_incidents.sql` ثم `0052` و`0053`. لم تُغيّر هذه الحزمة تاريخ الترحيلات؛ يجب أن يحسم مالكو الفروع التاريخ الموحد قبل اختبار ترقية الإصدار.
3. اختيار قاعدة وBucket منفصلين لـ staging، وتحديد مسار خاص للشبكة وأسماء المتغيرات؛ لا توجد قيم أسرار في هذا التقرير.
4. مراجعة الاحتفاظ القانوني وفحص ملفات التحقق وحذف الملفات المنتهية واليتيمة قبل قبول مستندات حقيقية.
5. اختيار مزودي SMS/AI/الدفع والمراقبة واعتماد البلد والامتثال والتكلفة. لا تعني الجاهزية التشغيلية أن المدفوعات أو المتطلبات القانونية جاهزة.
6. تحديد خطة إنفاق ومراقبة تطبيق حقيقية؛ لا توجد قياسات لخدمة التطبيق. السعر الوحيد المحسوب من الوثائق الحالية هو تخزين الـ bucket بمعدل 0.015 دولار لكل GB-month؛ الإجمالي الشهري غير قابل للتحقق حاليًا.

## ما لم يُنفذ

لم يتم النشر أو الدمج، ولم تُنشأ بيئة أو خدمة أو bucket، ولم تتغير الشبكة أو الأسرار، ولم تُعدّل قاعدة Railway أو تُنسخ بيانات خاصة، ولم يُفعّل PITR، ولم يُنفذ ترحيل أو استعادة. جميع هذه العمليات تحتاج موافقة صريحة محددة للبيئة والموارد.
